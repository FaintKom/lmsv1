# Замечания владельца по конструктору курсов — план (2026-08-19)

34 замечания из прохода по редактору курсов/уроков/заданий. Здесь они
разложены по этапам. Каждый этап перед кодом получает свою спеку через
`/speckit-specify` — этот файл только карта, не спека.

**Порядок этапов не случаен:** сначала архитектура урока (меняет то, куда
всё остальное встраивается), затем общая инфраструктура превью и
тест-режима (без неё половину пофиксов нельзя проверить), затем система
ответов, затем доводка конкретных типов.

## Чистка прода 2026-08-20

Владелец: «там должно быть много заданий, которые неправильно опубликованы,
их нужно удалить». Их оказалось не два, а **двадцать четыре** — по одному
почти на каждый тип, названия набраны вслепую («аа», «33», «авав»).
Двадцать лежали в уроке «66», три в «123», плюс SCORM-заглушка в витрине.

Отдельно нашлись **четыре висящих блока** — ссылки на задания, которых уже
нет, в опубликованных курсах Math 5 и Math 7. Уроки «Adding fractions»,
«Decimal arithmetic», «From equation to points» и «Solving linear equations»
задумывались с двумя заданиями и несли по одному. Ученик этого не видел
(плеер молча пропускает такой блок), учитель видел приглашение выбрать тип.

Порядок был обратным тому, о чём просили, и намеренно: сначала PR #410,
потом чистка. Иначе удаление 24 заданий создало бы **21 новую** висящую
ссылку — 21 из них стояло в страницах уроков.

| | до | после |
|---|---|---|
| Негодных заданий | 24 | 1 |
| Заданий всего | 143 | 121 |
| Висящих ссылок | 4 | 0 |
| Текстовых блоков с содержимым | 64 | 64 |

Оставлен намеренно `KS-SCORM_PACK-03` — витринная заглушка без ссылки
запуска, чинится ссылкой, а не удалением.

Двадцать одно из удалённых лежало в одном уроке: ровно тот случай, ради
которого в PR #410 появилась блокировка строк. Без неё чистка сработала бы
наполовину.

**Гонка в E2E, пойманная по дороге** (PR #408, прод e92d23d): журнал класса
тянет состав по сегодняшней дате, пока список занятий ещё летит, поэтому имя
ученика появляется раньше колонок дней. Проверка колонок стояла на умолчании
Playwright в 5 секунд рядом с проверкой ученика на 15 — на медленном раннере
это красный E2E у постороннего PR. Теперь таймаут один на обе.

## Проход по интерфейсу учителя 2026-08-20

Владелец: «проведи сессию где ты создаешь нормальные полностью заполненные
задания через интерфейс учителя… чтобы понять есть ли проблемы с
заполнением». Прошёл путь целиком: курс → урок → страница → задание.

| Находка | Состояние |
|---|---|
| **Текст урока стирается при правке.** Редактор отдаёт содержимое в TipTap, только если `body` — объект; у сеяных курсов это строка HTML, поэтому поле открывается пустым, а первое нажатие клавиши пишет пустой документ поверх. 63 блока в 60 уроках | отдельная задача, запущена |
| **Каждый урок подписан «No content yet».** Сводка не знает формата страниц | specs/029, PR #412, прод bff7896 |
| **Клик по названию курса ничего не делал** | PR #413 |
| **Заголовок пикера типов не переведён** | отдельная задача, запущена |
| **Тип задания нельзя посмотреть, не создав его.** Клик заводит строку в каталоге мгновенно, и рождается она с пустым ключом ответов. Отсюда все 23 удалённых | ждёт; файл занят другими правками |
| **Автосохранение молчит.** Кнопки сохранения нет, элемент статуса пуст | ждёт; тот же файл |
| **В каталоге заданий нельзя создать задание.** Не кнопки не хватает: `exercises.lesson_id` объявлен `NOT NULL`, задание без урока невозможно. В проде 121 задание, ни одного без привязки | нужна миграция и решение владельца |

Отвергнутая по дороге гипотеза: «блок удалили, задание осиротело». Проверено
живым сценарием — удаление блока сносит и задание. Мусор накопился иначе:
задания создавали и **оставляли**.

**Осталось от старого:** `interactive-taker`, `quiz-taker`, `file-uploader`
и пять компонентов в `components/submissions/exercises/` держат ветку
легаси-уроков (типы quiz / interactive / theory). В проде таких уроков нет —
уйдут вместе с `content_type` как признаком типа урока (спека `specs/027`
написана, ждёт решения владельца).

## Решения владельца (2026-08-19)

1. **Урок** — без типа, внутри блоки с типами. Этап 2 делается именно так.
2. **Слайдеры в графиках (15, 20)** — убираем из ученического режима.
3. **Bubble Sheet (32)** — разобраться, что это; превью нужно. Тип не прячем.
4. **Scatter plot (19), поле в диалоге (26)** — разбор кода, решение в
   спеках этапов 5 и 6.

Работа идёт по этапам по очереди, каждый через Spec Kit и скиллы.
