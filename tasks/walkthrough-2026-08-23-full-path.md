# Сквозной ручной прогон: школа с нуля, 2026-08-23

Проверяем продукт руками, глазами клиента: новая школа появляется, набирает
людей, ставит расписание, ведёт занятия. Всё через интерфейс. Ни одного действия
через API или базу.

- **Среда:** прод, https://grasslms.online
- **Браузер:** Chrome, расширение Claude in Chrome
- **Охват:** ядро и вторая волна (без CRM, биллинга, SCORM, 3D-мира)

## Правила прогона

1. **Пароли вводит владелец.** Я довожу до поля и передаю управление — на входе
   и в форме создания пользователя, где поле пароля обязательное.
2. **Одна роль на профиль Chrome.** Сессия лежит в httpOnly-куке, а окна одного
   профиля делят куки. Обычное окно плюс инкогнито дают две роли одновременно;
   больше — только отдельными профилями Chrome.
3. **Прод во время прогона не трогаем.** Мерж любого PR перезапускает
   контейнеры и обнулит половину наблюдений. Предупредить параллельные чаты.
4. **Ничего не чиню по ходу.** Находки копятся в разделе внизу. Починка —
   отдельной веткой со своей спекой, после прогона.
5. **Обход через API — сам по себе находка.** Если действие не делается в
   интерфейсе, так и записываем. Разовый обход допустим, только чтобы прогон не
   встал, и помечается явно.
6. **Каждая находка с доказательством:** чтение страницы, ошибка консоли или
   ответ сети, а не «показалось».

## Что считаю находкой

500 или 403 там, где роль имеет право; пункт меню, ведущий в пустоту; действие,
которое бэкенд умеет, а интерфейс не даёт; данные чужой школы в выдаче;
непереведённая строка; форма без валидации; кнопка без отклика.

## Журнал прогона

**Ф0, 2026-08-23.** В проде был коммит `22ac2eb1`. Открытых PR на момент проверки
не было, но соседняя сессия смержила #445 минутой раньше, и CI по `d7c0c123` шёл
уже во время подготовки. Прогон Ф1 отложен до конца деплоя.

`22ac2eb1` не давал завести школу: `POST /api/v1/admin/organizations` падал с
`ModuleNotFoundError: No module named 'python_slugify'` — импорт внутри
обработчика `admin/router.py:1197`, тогда как установленный пакет
`python-slugify` импортируется как `slugify`. Разобрано другой сессией по Sentry
и закрыто в `specs/046-admin-org-endpoints-500` вместе с каскадом при удалении
школы. Моей находкой не считается — записано, чтобы при чтении отчёта было ясно,
почему Ф1 начался позже.

Вкладка Chrome работала в фоне (`visibilityState: hidden`): скриншот отваливался
по таймауту, клики проходили через раз. Прогон продолжается только с развёрнутым
окном.

**Ф1, прод на `d7c0c123`.** Школа «E2E Школа 23.08» создана, `POST
/api/v1/admin/organizations` → 200, slug `e2e-shkola-23-08` (кириллица
транслитерирована верно), id `b917a614-2af5-471d-8077-8d63583a2736`.

Карточка школы открывается и читает именно её (`GET
/api/v1/admin/organizations/b917a614-…`), а не текущую. Переключателей меню
ровно 16, все включены — пустая карта `menu_visibility` читается как
«показывать», как и задумано в specs/040. Пункт «Waitlist» виден в меню, но
переключателя не имеет: он охраняется `isSuperAdmin`, школьный админ его не
видит вовсе. Не регрессия.

Мышь в этом прогоне мертва (окно Chrome свёрнуто, `visibilityState: hidden`):
страницы ведутся через `form_input` и `javascript_tool`, каждое нажатие
предваряется проверкой `elementFromPoint` — перекрытая или мёртвая кнопка была
бы видна. Не покрыто: дефекты, которые проявляются только на наведении.

### Н-02 · Школу создать можно, посадить в неё администратора — нечем
Где:      /admin/users, super admin, сразу после создания школы
Ожидал:   создавая пользователя, суперадмин выбирает школу — он только что её завёл
Получил:  в форме четыре поля: имя, почта, пароль, роль. Организации нет, хотя
          `POST /admin/users` принимает `org_id` от суперадмина
          ([admin/router.py:1057](backend/app/admin/router.py:1057)). Пользователь
          попадает в школу создающего. Замер после создания:
          `auth/me` → `org_id` Prog School, `me/memberships` → `[]`.
          Единственный путь дальше — выпадашка организации в строке таблицы,
          то есть завести человека не туда и переложить
Влияние:  мешает, и сильно: это первый шаг подключения новой школы, и он
          выглядит как ошибка оператора, а не как задуманный порядок

Замечание рядом: смена `org_id` через строку таблицы не заводит
`OrganizationMembership`. Значит `switch-org` для такого пользователя всё равно
ответит 403, и переключение между школами через интерфейс недостижимо.

### Н-03 · Массовый импорт заводит учеников, в которых нельзя войти
Где:      /admin/bulk-enroll, режим «Import Students Only», админ школы
Ожидал:   либо поле пароля по умолчанию, либо выдачу созданных паролей после импорта
Получил:  в этом режиме поля пароля нет вовсе (в соседнем, «Create & Enroll in

Влияние:  мешает — школа импортирует класс и остаётся без единого доступа;
          восстановление только сбросом пароля поштучно
