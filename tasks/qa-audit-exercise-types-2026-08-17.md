## Находка 1 — сервер отдаёт 500 на пустой ответ. Все интерактивные типы

**Серьёзность: высокая. ПОЧИНЕНО в этом же заходе.** Не «ноль баллов», а
необработанное исключение.

Починка — `_as_answer_dict` в [`submissions/service.py`](../backend/app/submissions/service.py):
нормализация входа в обеих публичных функциях грейдинга, то есть в одной точке
на все три места вызова. Регрессионный тест —
`tests/test_submissions.py::test_cleared_interactive_answer_scores_zero_instead_of_crashing`.
Порядок соблюдён: тест сначала показан падающим на `origin/main`
(`AttributeError: 'NoneType' object has no attribute 'get'`), затем зелёным;
34 теста `test_submissions.py` + `test_exercises.py` проходят.

Воспроизведение (любой интерактивный тип, здесь matching):

```
POST /api/v1/exercises/<id>/submit   {"interactive_answers": {}}
→ 500 Internal Server Error
```

Трейсбек:

```
File "/app/app/exercises/service.py", line 792, in _submit_interactive
File "/app/app/submissions/service.py", line 482, in _grade_map_pin_drop_detail
    student_pins = answers.get("pins", [])
AttributeError: 'list' object has no attribute 'get'
```

**Корень** — [`exercises/service.py:787`](../backend/app/exercises/service.py):

```python
interactive_answers = data.get("interactive_answers") or data.get("answers", {})
```

Две ошибки в одной строке:

1. `or` считает **пустой словарь ложным**. Студент, стёрший свой ответ, проходит
   мимо своего же поля.
2. Фолбэк `{}` **недостижим**. `data` приходит из `model_dump()`, ключ `answers`
   присутствует всегда, а по схеме
   ([`schemas.py:202`](../backend/app/exercises/schemas.py)) он
   `list[dict] | None = None`. Значит `.get("answers", {})` возвращает `None` или
   список — но никогда `{}`.

Дальше в грейдер уезжает не-словарь, а **все** грейдеры зовут `answers.get(...)`
без единой проверки типа — 18 вызовов в
[`submissions/service.py`](../backend/app/submissions/service.py).

Проверено по шести типам волны 1 — matching, ordering, categorize, crossword,
word_search, map_pin_drop: **500 у всех шести**.

Контрольный случай, доказывающий, что дело именно в этой строке: правильно
оформленный пустой ответ обрабатывается штатно.

| Запрос | Ответ |
|---|---|
| `{"interactive_answers": {}}` | **500** |
| `{"answers": []}` | **500** |
| `{"interactive_answers": {"pairs": []}}` | **200**, `score: 0`, `passed: false` |
| `{"interactive_answers": {"pairs": [ … верно … ]}}` | **200**, `score: 100` |

Починка — одна строка: различать «поля нет» и «поле пустое», и не пускать в
грейдер ничего, кроме словаря.

**Это тот случай, когда я предложу тест.** Не на весь пул типов — на эту строку:
пустой `interactive_answers` обязан давать 0 баллов, а не 500.

## Находка 2 — кнопка отправки выглядит активной, когда нажать нельзя

**Серьёзность: средняя. На телефоне — высокая.**

Из 11 кнопок отправки в волне 1 по-настоящему отключены только две — у
`word_search`: `disabled=true`, `opacity: 0.4`, видно глазом.

Остальные девять: `disabled=false`, **`opacity: 1`** — выглядят полностью
рабочими. Из них четыре несут `aria-disabled="true"`: клик по ним молча не делает
ничего. Ни сообщения, ни подсветки незаполненного, ни тряски.

Единственный визуальный признак — `cursor: not-allowed`. **На тач-устройстве
курсора нет вообще**, то есть мобильный студент жмёт кнопку и не получает ни
результата, ни объяснения.

Инверсия, которую стоит заметить: скринридер о блокировке узнаёт (`aria-disabled`
проставлен), а зрячий студент — нет.

## Находка 3 — кроссворд нерешаем: рендерер игнорирует конфиг задания

**Серьёзность: высокая. ПОЧИНЕНО** (`59ba620`, внутри PR #319) — задание было
невозможно выполнить. Виновата оказалась фикстура, не рендерер: адаптер и
`_grade_crossword_detail` читают `config["words"]`, а конфиг слал
`grid_width`/`grid_height`/`clues[]`. Диагноз ниже оставлен как был написан,
вместе с ошибкой в нём.

Уточнено измерением. Сетка **существует**: `.cw-grid`, 10 рядов, 110 ячеек. Но
ячейки пустые (`innerText` пуст, ни букв, ни номеров), а блок подсказок содержит
ровно одно слово — `CLUES`, без единой подсказки.

Фикстура при этом корректна:

```json
{"grid_width": 5, "grid_height": 5,
 "clues": [{"number": 1, "direction": "across", "answer": "CAT", "clue": "A small furry pet."},
           {"number": 2, "direction": "down", "answer": "CAR", "clue": "A road vehicle."}]}
```

5 × 5 = 25 ячеек, а отрисовано 110. Значит рендерер **не читает** ни
`grid_width`/`grid_height`, ни `clues` — он строит сетку по умолчанию и пустой
список подсказок. Студент видит пустое поле и слово «CLUES».

## Находка 4 — `max_attempts` не ограничивает попытки

**Серьёзность: высокая. ПОЧИНЕНО** (`59ba620`, внутри PR #319) — строка
исчерпания теперь пишется один раз, счётчик не уезжает. Проверено повторно
2026-08-18 на всех 26 типах. Остаток разобран в находке 10: строка эта несёт
`passed: true` при нулевом балле. Замер ниже — на код до починки.

| Попытка | Ответ | `attempts_remaining` | `max_attempts_reached` |
|---|---|---|---|
| 1 (неверно) | 200, score 0 | 1 | false |
| 2 (неверно) | 200, score 0 | 0 | **true** |
| 3 (неверно) | **200**, показан правильный ответ | 0 | true |
| 4 (**верно**) | **200, `passed: true`** | 0 | true |

Итог: `attempt_count: 4` при `max_attempts: 2`. Лимит не останавливает отправку —
студент спокойно сдаёт после исчерпания, причём на третьей попытке сервер уже
показал ему правильный ответ. Сдать верно после подсказки — 200 и `passed: true`.

Отдельно: четвёртый ответ вернулся с `passed: true` **и `score: 0`
одновременно**. Что из этого попадёт в журнал — из ответа не следует.

## Ось C — перезагрузка посреди ответа

**Ответ структурный, а не выборочный: черновик не сохраняется ни у одного типа.**

`grep` по `frontend/src/components/exercises/` даёт **ноль** обращений к
`localStorage` и `sessionStorage`. Единственное, что похоже на сохранение, —
`onAnswersChange` в v2-компонентах, но это поток в живой урок, чтобы учитель
видел ход решения; работу студента он не восстанавливает. На сервер попадает
только отправленное. Значит незавершённый ответ живёт исключительно в состоянии
React и умирает от F5 — во всех 26 типах.

Подтвердить это кликом в браузере на волне 1 не удалось: выбранное задание уже
имело оценённую отправку и перестало принимать ввод (см. находку 5). Помечаю
честно: **вывод сделан по коду, интерактивного подтверждения нет.**

## Находка 5 — решённое задание выглядит нерешённым и не реагирует

**Серьёзность: высокая. ПОЧИНЕНО** (`735e559`, внутри PR #319) — восстановление
результата было под `if (last_submission.passed)`, поэтому неверная сдача
выглядела как отсутствие сдачи. Замер ниже — на код до починки.

Замерено на QA-стеке, matching, после отправки с
`score: 100`.

Студент возвращается к заданию, которое сдал верно, и видит:

- тот же призыв к действию: «CONNECT EVERYTHING AND PRESS CHECK · TAP A LINKED
  TILE TO UNHOOK THE THREAD»;
- плитки с `disabled: false` и `pointerEvents: auto` — выглядят рабочими, но
  нажатия ничего не меняют (класс `linked` не появляется);
- кнопку «Check» с `opacity: 1` и `aria-disabled="true"` — выглядит нажимаемой,
  молчит.

Ни оценки, ни отметки «выполнено», ни правильного ответа. Интерфейс не отличает
«ещё не решал» от «решено на сто баллов» и в обоих состояниях предлагает
действие, которого не выполняет. Та же болезнь, что в находке 2, но в худшем
месте: после успеха.

## Находка 6 — ненастроенное задание ставит всем полный балл

**Серьёзность: высокая. ЧАСТИЧНО** (`ae67aa4`, внутри PR #319): грейд намеренно
не менялся — ноль вместо ста наказывал бы студента за чужую ошибку в настройке.
Добавлено предупреждение в лог для девяти типов, чьи грейдеры прочитали. Прогон
2026-08-18 нашёл дыру в этой заплатке: `bubble_sheet` в список не попал, ставит
100 всем и не пишет ни строчки. Разбор — находка 9.

`_grade_crossword_detail` при пустом `content["words"]` отвечает `1.0, True`.
Пока фикстура кроссворда была в неверном формате, задание было нерешаемым **и**
выдавало 100 % за ничто.

Это не частный случай: шаблон `if not <config>: return 1.0, True` встречается в
[`submissions/service.py`](../backend/app/submissions/service.py) **двенадцать
раз** — matching, ordering, fill_blanks, categorize, dialogue, conjugation,
reading, bubble_sheet, crossword, word_search и другие. Любое неверно
настроенное интерактивное задание молча ставит всем полный балл, и заметить это
некому: журнал видит «сдано».

## Находка 7 — у math_interactive задание на экране и условие проверки расходятся

**Серьёзность: средняя.** Замерено на QA-стеке.

Студент видит две инструкции сразу:

```
📝 Click the origin.
Drag each point to its target:  A → (3, 2)   B → (-2, 4)
```

А грейдится `success_condition: {"kind": "click_origin"}`. Перетаскивание точек ни
на что не влияет: кто аккуратно поставил A и B, но не кликнул начало координат —
не сдал; кто проигнорировал точки и кликнул — сдал.

Источник расхождения — фикстура (`instructions` и `success_condition` заданы
независимо), то есть данные этого прогона, а не продуктовый код. Но заметить
стоит другое: **ничто не проверяет, что описание задания и условие его проверки
говорят об одном и том же.** Учитель соберёт такое же руками, и ему никто не
возразит.

## Находка 8 — неверный тип внутри ответа роняет сервер. Шесть типов

**Серьёзность: высокая.** Не отказ, а необработанное исключение: 500 и пустой
`{"detail":"Internal server error"}` студенту.

Починка волны 1 нормализовала **контейнер**: `interactive_answers` обязан быть
словарём. Значения внутри остались непроверенными, и три разных корня дают один
и тот же результат.

| Тип | Что послано | Ответ | Исключение |
|---|---|---|---|
| `crossword` | `{"words": "not-a-dict"}` | **500** | `AttributeError: 'str' object has no attribute 'get'` |
| `map_pin_drop` | `{"pins": "not-a-list"}` | **500** | то же |
| `robot_2d` | `{"game_result": {"score": "lots"}}` | **500** | `ValueError: could not convert string to float: 'lots'` |
| `world_3d` | то же | **500** | то же |
| `math_interactive` | то же | **500** | то же |
| `web_editor` | `{"web_code": {"html": []}}` | **500** | `TypeError: expected str, got list` из asyncpg |

Корни:

1. `_grade_crossword_detail` и `_grade_map_pin_drop_detail` зовут `.get(...)` и
   индексируют пришедшее, не спрашивая типа
   ([`submissions/service.py`](../backend/app/submissions/service.py)).
2. `_submit_game_level` делает `float(game_result["score"])`
   ([`exercises/service.py:1089`](../backend/app/exercises/service.py)).
3. `_submit_web_editor` кладёт `web_code["html"]` прямо в колонку `source_code`
   типа VARCHAR, и список доезжает до драйвера
   ([`exercises/service.py:1139`](../backend/app/exercises/service.py)).

Общее у всех трёх: `SubmitExerciseRequest` объявляет `game_result` и `web_code`
голым `dict`, а `interactive_answers` — словарём без описания значений. Схема
проверяет внешнюю скобку и на этом останавливается.

Контроль на месте: те же шесть типов на правильном ответе отвечают 200.

## Находка 9 — bubble_sheet ставит 100 всем, и предупреждение молчит

**Серьёзность: высокая.** Задание, которое невозможно не сдать.

| Что послано | Ответ |
|---|---|
| правильные ответы из фикстуры | 200, `score: 100` |
| **пустой** `{"interactive_answers": {}}` | **200, `score: 100`, `passed: true`** |
| ответ неверного типа | **200, `score: 100`** |

Причина — расхождение ключей, ровно как у кроссворда 2026-08-17.
`_grade_bubble_sheet_detail` читает `content["questions"]` и берёт у каждого
вопроса `q["correct"]`, а фикстура пишет `question_count`,
`choices_per_question` и `correct_answers`. Вопросов грейдер не находит и
отвечает `1.0, True` — тот самый шаблон из находки 6.

Хуже второе. Предупреждение, добавленное в `ae67aa4` ради этого случая, не
сработало: `grep "empty answer key"` по логам бэкенда за весь прогон — **ноль
строк**. В списке наблюдения `_ANSWER_KEY_BY_TYPE` девять типов, и
`bubble_sheet` в него не входит, как и `dialogue`, `translation`,
`sentence_builder`, `map_pin_drop`. Список делали сознательно неполным, чтобы не
врать предупреждениями; первое же задание вне списка прошло молча.

## Находка 10 — исчерпав попытки, студент числится сдавшим с нулём

**Серьёзность: средняя, для журнала высокая.** Воспроизводится на **всех** типах
с `max_attempts = 2`: 26 копий V2 отвечают одинаково.

Счётчик держится: починка `59ba620` работает, строка исчерпания пишется один раз

в базе.

## Находка 11 — эталонное решение code_challenge не проходит собственные тесты

**Серьёзность: средняя. Данные, а не код.**

`solution_code` в фикстуре — `def add(a, b): return a + b`. Тест-кейсы подают
`1 2` на stdin и ждут `3` на stdout. Функция ничего не читает и ничего не
печатает: песочница отработала штатно (`status: success`, 19 мс, пустой
`stderr`), `actual` пустой, оба теста провалены, `score: 0`.

Решить такое задание студент может, только догадавшись, что от него хотят не
функцию, а программу. Фикстура общая: она же кормит `seed_qa.py` и курс Kitchen
Sink, по которому кликают руками.

Здесь не чинилось намеренно: правка фикстуры меняет данные, которые читает
Playwright-гейт на каждом PR (FR-010). Отдельной задачей — либо переписать
`solution_code` под stdin/stdout, либо перевести тест-кейсы на вызов функции.
