# Implementation Plan: Один список пунктов меню вместо двух

**Branch**: `claude/magical-burnell-40a406` | **Date**: 2026-08-22 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/040-menu-keys-one-list/spec.md`

## Summary

Список переезжает к меню. `MENU_ITEM_KEYS` уходит из `org-settings-form.tsx` в
`nav-tree.ts` — туда, где объявлены сами пункты, — и форма импортирует его
оттуда. Два списка остаются двумя, но лежат в одном файле, на расстоянии
экрана, и разойтись незаметно им больше негде.

Заодно исчезает второй набор подписей. Переключатели берут те же ключи `nav.*`,
которыми подписаны пункты меню; десять ключей `admin.settings.menu*` не нужны
никому и удаляются из шести локалей. Новых строк перевода — ноль, удалённых —
шестьдесят.

Забор от следующего расхождения — не сверка руками, а Proxy. Тест подсовывает
`buildNavTree` карту видимости, которая записывает каждый спрошенный ключ, и
сравнивает набор спрошенного с набором предложенного. Ключ, добавленный в меню
и забытый в списке, красит CI; ключ, оставшийся в списке после удаления пункта
(вся история `meetings`), — тоже.

## Technical Context

**Language/Version**: TypeScript 5, React 19

**Primary Dependencies**: Next.js 16, Vitest

**Storage**: не меняется — `organizations.settings.menu_visibility` (JSONB),
миграции нет

**Testing**: Vitest (`nav-tree.test.ts`, `translations.test.ts`), затем живая
проверка в браузере

**Target Platform**: веб

**Project Type**: web application — правка целиком во `frontend/`

**Constraints**: шесть локалей обязаны совпадать по ключам; новый `.tsx` не
создаётся, значит i18n-ратчет не задет

**Scale/Scope**: было 10 переключателей, стало 16; один перенос, одно удаление,

## Constitution Check

- **Изоляция арендаторов**: карта видимости и так своя у каждой школы, читается
  из `/auth/me` по токену. Правка ничего не переносит между школами.
- **Тесты, которые способны упасть**: тест сравнивает два множества строк;
  он красный при расхождении в любую сторону. Проверяется обоими способами —
  добавлением лишнего ключа в список и удалением нужного.
- **Серверная проверка ответов**: не относится. Отдельно записано в спеке:
  спрятать пункт — не закрыть доступ, права по-прежнему на сервере.

## Решения

**Почему список переезжает к меню, а не наоборот.** Ключ существует, потому что
его спрашивает `buildNavTree`. Форма — потребитель: она пишет ответы на вопросы,
которые задаёт меню. Список, живущий у потребителя, отстаёт от источника — это и
произошло.

**Почему не вывести список из дерева автоматически.** Ключи вписаны внутрь
условий показа (`isAdminOnly && visible("crm")`), и вытащить их без разбора
выражений нельзя. Разбирать — значит переписывать `buildNavTree` ради списка,
который меняется раз в полгода. Дешевле объявить рядом и поймать расхождение
тестом.

**Почему Proxy, а не список ключей в тесте третьей копией.** Третья копия
разойдётся так же, как разошлась вторая. Proxy не хранит ничего — он записывает,
про что меню спросило на самом деле, и потому не может устареть.

**Почему подписи `nav.*`.** Переключатель прячет пункт меню, значит должен
называться так, как называется пункт. Второй набор подписей не давал ничего,
кроме возможности разойтись, — и уже разошёлся на «Review» против «Review Queue».

**Почему список остался плоским.** Шестнадцать строк с заголовками групп — это
ещё пять элементов на экране ради порядка, который и так виден: переключатели
идут ровно так, как идут пункты в меню. Заголовки добавим, если станет тесно.

## Проверка

1. `npx vitest run nav-tree translations no-hardcoded-strings` — зелёные, и новая
   проверка красная, если сломать любой из двух списков.
2. `npx tsc --noEmit` — гейт CI.
3. В браузере под администратором: выключить «Заявки», сохранить, обновить —
   пункт пропал из меню; включить обратно — вернулся.
4. Прочитать список настроек глазами: шестнадцать переключателей, подписи те же,
   что в меню, «Пользователи» / «Заявки» / «Траектории» помечены как
   административные.
