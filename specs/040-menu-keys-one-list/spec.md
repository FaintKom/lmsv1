# Feature Specification: Один список пунктов меню вместо двух

**Feature Branch**: `claude/magical-burnell-40a406`

**Created**: 2026-08-22

**Status**: Draft

**Input**: Вынесено из `specs/039-dead-menu-visibility-key` — раздел «Out of scope».
Меню умеет прятать шестнадцать пунктов, форма настроек предлагает выключить
десять.

## Что происходит сейчас

Школа открывает «Настройки», раздел «Видимость меню», и видит десять
переключателей. Пунктов, которые меню умеет прятать, — шестнадцать.

Шесть, до которых школа не дотянется: «Библиотека контента», «Взаимная
проверка», «Командные проекты», «Заявки», «Журнал», «Поддержать». Меню про
каждый из них спрашивает карту видимости, но записать в карту «нет» может только
форма, а форма о них не знает. Значит выключить их нельзя ничем.

Отказа никто не видит. Пункта нет в списке — и школа не узнаёт, что он вообще
скрываем.

## Почему так вышло

Списков два, и они не связаны. Один — внутри `buildNavTree`, где ключ вписан в
условие показа каждого пункта. Второй — `MENU_ITEM_KEYS` рядом с формой. Пункт
добавляют в меню, а во второй список забывают; или удаляют из меню, а во втором
он остаётся. Второе уже случилось: ключ `meetings` дожил в проде до отдельной
миграции (`specs/039`).

У списков разошлись и подписи. Меню зовёт очередь «Review», форма — «Review
Queue», хотя это один и тот же пункт. Десять подписей продублированы в шести
локалях — шестьдесят строк, которые существуют только чтобы разойтись с теми,
что рядом.

## Что это не решает

Спрятать пункт — не то же самое, что закрыть доступ. Преподаватель, знающий
адрес, откроет `/admin/journal` по прямой ссылке и после правки: меню управляет
меню, права проверяет сервер. Правка ничего здесь не меняет и не должна.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Школа выключает любой пункт, который меню умеет спрятать (P1)

Школа не ведёт приём заявок и хочет убрать «Заявки» из меню. Открывает
настройки, находит переключатель, выключает.

**Why this priority**: ради этого правка и делается.

**Independent Test**: выключить один из шести недоступных сегодня пунктов и
убедиться, что он пропал из бокового меню.

**Acceptance Scenarios**:

1. **Given** школа открыла настройки, **When** она смотрит на список видимости,
   **Then** в нём есть переключатель для каждого пункта, который меню умеет
   спрятать, — и ни одного лишнего.
2. **Given** школа выключила «Заявки» и сохранила, **When** администратор
   обновляет страницу, **Then** пункта нет в боковом меню.
3. **Given** школа ничего не меняла, **When** она сохраняет настройки,
   **Then** ни один пункт не исчез: неизвестные форме ключи она пишет как
   «показывать».

---

### User Story 2 — Переключатель называется так же, как пункт меню (P2)

Школа читает список настроек и узнаёт в нём своё меню.

**Why this priority**: без этого список из шестнадцати строк приходится сверять
с меню по догадке. Дешевле следствия основной правки, чем отдельная работа.

**Independent Test**: сравнить подписи переключателей с подписями пунктов
бокового меню — они совпадают дословно.

**Acceptance Scenarios**:

1. **Given** пункт меню называется «Review», **When** школа ищет его в
   настройках, **Then** переключатель называется «Review», а не «Review Queue».

---

### User Story 3 — Расхождение списков ловится до прода (P3)

Тот, кто добавит или уберёт пункт меню, узнаёт о забытом списке от CI.

**Why this priority**: сама по себе ценности для школы не несёт, но без неё
правка живёт до следующего пункта меню.

**Independent Test**: добавить в меню пункт с новым ключом и не тронуть список
настроек — проверка падает.

**Acceptance Scenarios**:

1. **Given** меню спрашивает карту про ключ, которого нет в списке настроек,
   **When** проходит проверка, **Then** она красная и называет лишний ключ.
2. **Given** в списке настроек есть ключ, про который меню не спрашивает,
   **When** проходит проверка, **Then** она красная — это и есть история
   `meetings`.

### Edge Cases

- Пункт, который меню показывает только супер-администратору
  (`/admin/organizations`, `/admin/waitlist`, `/admin/integrations`,
  `/admin/settings`), карту видимости не спрашивает вовсе. Такие в списке
  настроек не появляются: выключать нечего.
- Пункт, доступный только администратору («Пользователи», «Заявки»,
  «Траектории»), помечен как таковой — иначе школа выключает его «для
  преподавателей», а те его и так не видели.
- У школы в карте нет ни одного из шести новых ключей. Отсутствие значит
  «показывать» — меню не меняется, пока школа сама не выключит.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Список настроек MUST предлагать переключатель ровно для тех ключей,
  которые меню спрашивает у карты видимости, — ни больше, ни меньше.
- **FR-002**: Подпись переключателя MUST быть той же строкой, что и подпись
  соответствующего пункта меню.
- **FR-003**: Переключатель для пункта, доступного только администратору, MUST
  быть помечен как административный.
- **FR-004**: Порядок переключателей MUST повторять порядок пунктов в меню.
- **FR-005**: Расхождение двух списков MUST быть поймано проверкой, которая
  падает, — а не обнаружено в проде.
- **FR-006**: Правка MUST не менять того, что видит школа, пока школа сама
  ничего не выключила.
- **FR-007**: Правка MUST не добавлять ни одной новой строки перевода: подписи
  уже есть во всех шести локалях.

### Key Entities

- **Ключ пункта меню**: строка, по которой меню спрашивает карту видимости и по
  которой форма пишет в неё ответ. Сегодня объявлена дважды, должна — один раз.
- **Карта видимости (`settings.menu_visibility`)**: ключ → показывать ли пункт.
  Отсутствие ключа значит «показывать».

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Число переключателей в настройках равно числу ключей, которые
  спрашивает меню. Сегодня 10 против 16, после правки 16 против 16.
- **SC-002**: Каждый из шести ранее недоступных пунктов выключается из интерфейса
  и пропадает из меню.
- **SC-003**: Ни одной новой строки перевода; удалённых — шестьдесят.
- **SC-004**: Проверка падает, если в любом из двух списков появится ключ,
  которого нет в другом.

## Assumptions

- Все шестнадцать пунктов школа вправе прятать. Меню уже спрашивает карту про
  каждый из них — правка не расширяет право прятать, а даёт дотянуться до того,
  что меню и так умеет.
- Подписи `nav.*` есть во всех шести локалях для всех шестнадцати ключей —
  проверено.
- Ключи `admin.settings.menu*` не используются нигде, кроме списка настроек —
  проверено; удаление ничего не оставит без подписи.
