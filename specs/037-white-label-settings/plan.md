# Implementation Plan: White-label settings in one place

**Branch**: `feat/white-label-settings` | **Date**: 2026-08-21 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/037-white-label-settings/spec.md`

## Summary

Бренд школы доходит до трёх мест и там останавливается. Второй фирменный цвет
школа выбирает вхолостую — `var(--secondary)` не читает ни одна строка проекта.
Цвет текста на фирменном цвете фиксирован и из выбранного цвета не выводится,
поэтому светлый бренд даёт белый текст на светлом фоне, молча.

Работа делает три вещи. Чинит вывод читаемого цвета — из константы он
становится расчётом. Даёт второму цвету работу в трёх конкретных местах.
Расширяет охват бренда на вкладку браузера, страницу входа, публичную страницу
заявки и контакт поддержки, собирая всё управление этим на одной странице
настроек. Плюс превью, где цвет виден на живых элементах в обеих темах до
сохранения.

Подход целиком в [research.md](./research.md): чистый модуль расчёта контраста
вместо двух копий эффекта в лэйаутах; расширение существующего публичного
ответа вместо нового эндпоинта; встроенный сценарий в `<head>` по образцу уже
работающего переключателя темы; ноль новых маршрутов.

## Technical Context

**Language/Version**: TypeScript 5 strict (фронтенд), Python 3.12 (бэкенд)

**Primary Dependencies**: Next.js 16 App Router, React 19, Tailwind 4, TanStack
Query 5, Zustand 5, Recharts; FastAPI, SQLAlchemy 2 async, Pydantic v2

**Storage**: PostgreSQL 16. `Organization.settings` — `JSONB`,
`Organization.slug` — существующая колонка. **Миграций нет.**

**Testing**: Vitest + Testing Library (юниты), Playwright (сквозные), pytest
(бэкенд). Все три — обязательные проверки CI.

**Target Platform**: браузер; прод — Hetzner CX22 за nginx

**Project Type**: веб-приложение, фронтенд и бэкенд в одном репозитории

**Performance Goals**: превью перерисовывается на каждое изменение цвета без
запроса к серверу. Расчёт контраста — синхронный, на двоичном поиске по
светлоте, без измеримой задержки на ввод.

**Constraints**:

- Порог контраста 4.5:1 (WCAG AA, обычный текст) — он уже принят в проекте.
- Ратчет i18n: новый `.tsx` обязан звать `useTranslation()`; ключи во всех шести
  локалях в той же правке, иначе падает `translations.test.ts`.
- Вызовы API — через `src/lib/api/*`, не `apiClient` в компоненте.
- Токены Lively; белый текст на солнечных поверхностях запрещён всегда.
- **Ноль новых маршрутов.** Каждый маршрут утяжеляет `next build`, который
  когда-то уронил прод-бокс.

**Scale/Scope**: школы на 10–300 учеников. Затрагивается ~14 файлов фронтенда и
2 бэкенда; создаётся 5 новых файлов; удаляется дублированный эффект из двух
лэйаутов.

## Constitution Check

*GATE: пройден до Phase 0, перепроверен после Phase 1.*

| Принцип | Как соблюдается | Где проверяется |
|---|---|---|
| **I. Изоляция арендаторов — правило, а не привычка** | Новые ключи едут по существующему `PUT /admin/organizations/{org_id}`, где изоляция уже работает; обходного пути не появляется. Публичный ответ расширяется **только** оформлением: контакт поддержки, состав меню и значок вкладки в него не попадают. Неактивная и несуществующая школа дают одинаковый 404 — поведение `service.public_school:240` не трогается. | quickstart: раздел «Изоляция арендаторов», открывается положительным контролем |
| **II. Тест, способный упасть** | Обе главные проверки красные против нынешнего кода: цвет текста сегодня не зависит от фирменного цвета (константа `--primary-fg`), а второй цвет сегодня не читает никто. Демонстрация падения указывается в теле PR. | quickstart 1 и 3 |
| **III. Сервер — единственный судья ответа** | Не затрагивается: работа не касается проверки ответов. | — |
| **IV. Продукт и документы говорят одно** | `localStorage["school-slug"]` — новая запись на устройстве, и строка в таблице на `/cookies` появляется **в той же правке**. Это задача, а не заметка на будущее. | quickstart 5, шаг 4 |
| **V. Наименьшее изменение** | Ноль новых маршрутов, ноль новых эндпоинтов, ноль миграций. Дублированный эффект из двух лэйаутов удаляется. Два литеральных hex в графике уходят. Второй цвет сохранён по решению владельца — нарушение снимается тем, что поле получает работу. | research R2, R3, R6, R7 |

**Нарушений нет.** Раздел «Complexity Tracking» пуст намеренно.

**Что здесь могло бы нарушить принцип I и не нарушает.** Публичный ответ по
слагу — единственное место, где эта работа расширяет то, что видно без входа.
Ограничение состава `branding` четырьмя полями и отдельный файл
`public_router.py`, где публичная поверхность видна в дереве файлов, — то, что
удерживает это в рамках. Добавляемое ограничение частоты закрывает вторую
сторону: у адреса появляется потребитель, который бьёт по нему на каждый показ
формы входа.

`backend/app/crm/service.py` в списке нет намеренно: `public_school` уже делает
ровно то, что требует FR-025, и трогать его не нужно.

**Structure Decision.** Существующее разделение фронтенда и бэкенда в одном
репозитории. Новых каталогов верхнего уровня нет; `lib/brand/` — единственный
новый подкаталог, и он заведён потому, что расчёт контраста нужен двум
несвязанным потребителям (лэйауту и форме) и должен проверяться без рендера —
как уже сделано с `nav-tree.ts`.

Ни одного нового маршрута: `/login`, `/s/[slug]/enquire`, `/support`,
`/admin/settings` и `/admin/organizations/[orgId]` уже существуют.
