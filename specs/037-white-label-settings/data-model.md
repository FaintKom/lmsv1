## Organization.settings

Свободный по составу словарь. Существующие ключи остаются как есть; новые
добавляются рядом.

| Ключ | Тип | Есть сегодня | Пример | Пусто значит |
|---|---|---|---|---|
| `display_name` | строка | да | `Prog School` | берётся `Organization.name` |
| `logo_url` | адрес | да | `https://cdn.example/logo.svg` | буквенный значок с названием |
| `primary_color` | `#rrggbb` | да | `#22c55e` | цвет продукта |
| `secondary_color` | `#rrggbb` | да | `#3b82f6` | подставляется от основного |
| `secondary_is_custom` | булево | **нет** | `true` | второй цвет следует за основным |
| `favicon_url` | адрес | **нет** | `https://cdn.example/icon.png` | значок продукта |
| `support_email` | почта | **нет** | `help@example.school` | ведёт на `/support` |
| `support_url` | адрес | **нет** | `https://example.school/help` | ведёт на `/support` |
| `menu_visibility` | словарь | да | `{"paths": false}` | всё видно |

### `secondary_is_custom` — почему это отдельный флаг

Без него «школа выбрала второй цвет сама» неотличимо от «второй цвет совпал с
предложенным». Сравнить `secondary_color` с расчётным нельзя: школа могла
осознанно выбрать ровно тот оттенок, который мы предложили, и тогда любое
изменение основного цвета молча увело бы её выбор.

Ставится в `true` ровно один раз — когда администратор трогает поле второго
цвета или выбирает образец. Никогда не снимается автоматически (FR-010).

### Проверки при сохранении

| Поле | Правило | Нарушено — что происходит |
|---|---|---|
| `primary_color`, `secondary_color` | `#` и шесть шестнадцатеричных цифр | 422 с указанием поля |
| `logo_url`, `favicon_url` | схема `https:` | 422 |
| `support_url` | схема `https:` | 422 (FR-033) |
| `support_email` | обычная проверка почты | 422 (FR-033) |

Схемы, кроме `https:` и `mailto:`, запрещены. `javascript:` в ссылке, по
которой ходит каждый ученик школы, — дыра, а не удобство.

**Контраст не проверяется на сервере.** Цвет с плохим контрастом сохраняется:
предупреждение показывает форма, но не блокирует (FR-018). Сервер судит о
допустимости значения, а не о вкусе.

## Что вычисляется, а не хранится

Ничего из перечисленного в базе нет и быть не должно — всё выводится из
`primary_color` и `secondary_color` на клиенте (`lib/brand/contrast.ts`):

| Величина | Как получается |
|---|---|
| `--primary-fg` | тот из белого и почти-чёрного, что даёт больший контраст к заливке |
| цвет ссылки на светлом фоне | тон основного цвета, затемнённый до 4.5:1 |
| цвет ссылки на тёмном фоне | тот же тон, осветлённый до 4.5:1 |
| четыре предложения второго цвета | сдвиг тона на 40°, 180°, 120°, 210° |
| предупреждение о контрасте | лучший вариант текста на заливке ниже 4.5:1 |
| предупреждение о близости | контраст между двумя цветами ниже 1.3:1 |

Хранить их — значит завести второй источник правды, который разойдётся с
первым при первой же правке цвета.

## На устройстве ученика

`localStorage`, три ключа. Первые два существуют; третий добавляется этой
работой и **в той же правке появляется строкой в таблице на `/cookies`**
(принцип IV).

| Ключ | Есть | Значение | Кто пишет |
|---|---|---|---|
| `theme` | да | `light` / `dark` / `system` | переключатель темы |
| `sidebar-collapsed` | да | состояние меню | `ui-store` |
| `school-slug` | **нет** | `sunrise` | страница входа после успеха |

`school-slug` ничего не открывает и ничем не является, кроме подсказки, чей
логотип показать на входе. Устаревший или неизвестный — нейтральный экран, вход
работает.

## Публичное описание школы

`GET /api/v1/crm/public/{slug}` — существующий ответ дополняется одним полем.

```json
{
  "name": "Prog School",
  "slug": "sunrise",
  "courses": [{ "id": "...", "title": "Python from scratch" }],
  "branding": {
    "display_name": "Prog School",
    "logo_url": "https://cdn.example/logo.svg",
    "primary_color": "#22c55e",
    "secondary_color": "#3b82f6"
  }
}
```

Ключи внутри `branding` — только эти четыре. Контакт поддержки, состав меню и
значок вкладки **сюда не попадают**: они нужны вошедшему, а не прохожему, и
каждое лишнее поле в публичном ответе — то, что кто-то однажды соберёт по всем
слагам подряд.

Неактивная школа и несуществующая дают одинаковый 404 — это уже поведение
`service.public_school:240`, и новые поля его не меняют.
