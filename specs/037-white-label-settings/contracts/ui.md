# Interface Contracts: White-label settings

**Date**: 2026-08-21 · **Spec**: [spec.md](../spec.md)

Что эта работа обещает наружу. Всё, чего здесь нет, менять нельзя.

---

## 1. `lib/brand/contrast.ts` — чистые функции

Без React, без DOM, без сети. Проверяются Vitest напрямую, как `nav-tree.ts`.

| Функция | Вход → выход | Обещание |
|---|---|---|
| `contrastRatio(a, b)` | два `#rrggbb` → число | WCAG 2.1, от 1 до 21, симметрична |
| `readableOn(fill)` | `#rrggbb` → `#ffffff` \| `#0b0b0b` | тот из двух, чей контраст к заливке выше |
| `readableAs(color, bg)` | два `#rrggbb` → `#rrggbb` | тот же тон, доведённый до ≥ 4.5:1 к `bg`; если недостижимо — предельный |
| `suggestSecondary(primary)` | `#rrggbb` → четыре `#rrggbb` | сдвиг тона 40°, 180°, 120°, 210°; порядок устойчив |
| `tooClose(a, b)` | два `#rrggbb` → булево | `contrastRatio < 1.3` |

**Устойчивость порядка в `suggestSecondary` — часть контракта.** Первый элемент
подставляется как значение по умолчанию; если порядок поплывёт, у школ, не
выбравших второй цвет вручную, он молча сменится при следующем сохранении.

**Тон не меняется.** `readableAs` двигает светлоту, не оттенок: фирменный цвет
школы должен оставаться узнаваемым (FR-007).

## 2. `<BrandVars />` — применение цветов

Один клиентский компонент вместо двух копий эффекта в лэйаутах.

**Обещает:**

- школа без `primary_color` — ни одна переменная не трогается, продукт выглядит
  как сегодня (FR-034);
- `--primary-fg` переопределяется только когда задан `primary_color`;
- при уходе со страницы все выставленные переменные снимаются — суперадмин,
  посмотревший чужую школу, не уносит её цвета к себе (FR-004).

**Не обещает** ничего про тёмную тему сверх того, что уже делает
`document.documentElement.classList.toggle('dark', …)`.

## 3. `<BrandPreview primary secondary />`

**Вход:** два цвета. Больше ничего.

**Обещает:**

- перерисовку на каждое изменение входа, без сети и без сохранения (FR-014);
- собственный переключатель светлой и тёмной темы, не трогающий тему
  приложения (FR-015);
- образцы: кнопка основного действия, активный пункт меню, ссылка, метка,
  отметка достижения, две серии графика (FR-013);
- предупреждение при контрасте текста на заливке ниже 4.5:1 с указанием
  достигнутого значения (FR-016);
- предупреждение при `tooClose(primary, secondary)` (FR-017).

**Не имеет доступа** к организации, к сохранению и к сети. Если этому
компоненту однажды понадобится `orgId` — граница проведена неверно.

## 4. `buildNavTree` — новый вход

Функция уже существует (`components/layout/nav-tree.ts`). Добавляется поле:

```
supportHref?: string   // "mailto:help@example.school" | "https://example.school/help"
```

| Значение | Куда ведёт пункт «Поддержка» |
|---|---|
| не задано | `/support` — как сегодня (FR-032) |
| `mailto:` или `https:` | по указанному адресу (FR-031) |
| любая другая схема | считается незаданным |

Проверка схемы стоит **и** здесь, и при сохранении. Дважды намеренно: значение
приходит из базы, и запись могла попасть туда до появления проверки.

## 5. `GET /api/v1/crm/public/{slug}`

Существующий публичный ответ. Добавляется поле `branding` — состав в
[data-model.md](../data-model.md).

**Что не меняется:**

- неактивная и несуществующая школа дают одинаковый 404
  (`service.public_school:240`);
- аутентификация не требуется и не появляется;
- набор полей вне `branding` остаётся прежним.

**Что добавляется:** ограничение частоты. Сегодня его на этом GET нет, а со
страницей входа в роли второго потребителя адрес начинает получать запрос на
каждый показ формы.

---

## 6. `PUT /api/v1/admin/organizations/{org_id}`

Существующий эндпоинт. Новые ключи `settings` едут по нему же.

**Что не меняется — и это главное:** изоляция арендаторов. Администратор чужой
школы получает 404, суперадмин правит любую (FR-003, принцип I). Новые поля не
заводят обходного пути.

`settings` сливается, а не заменяется: частичное сохранение не должно стирать
ключи, которых не было в запросе.

## 7. `localStorage["school-slug"]`

| | |
|---|---|
| Пишет | страница входа, после успеха |
| Читает | страница входа при открытии; встроенный сценарий в `<head>` |
| Значение | слаг школы, `sunrise` |
| Неизвестный или устаревший | нейтральный экран, вход работает (FR-025) |

**Обязательство, а не побочный эффект:** строка в таблице на `/cookies`
появляется в той же правке (принцип IV).
