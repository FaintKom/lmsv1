# Implementation Plan: Спрятанный пункт меню спрятан и у преподавателя

**Branch**: `fix/menu-visibility-for-teachers` | **Date**: 2026-08-20 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/034-menu-visibility-for-teachers/spec.md`

## Summary

Карта видимости меню едет к клиенту тем же ответом, что и логотип школы, —
внутри `org_branding` в `GET /api/v1/auth/me`. Боковое меню перестаёт спрашивать
настройки отдельным запросом и читает их из хранилища сессии.

Организацию для этого ответа определяет токен, а не параметр запроса: чужой
идентификатор подставить некуда. Запрос при этом не дорожает — `organization`
уже подгружается через `selectinload` в `get_user_by_id`
(`backend/app/auth/service.py:248`), и `/auth/me` уже читает из неё
`display_name`.

Итог по строкам: на бэкенде прибавляется одна, на фронтенде убавляется восемь.

## Phase 1 — что именно меняется

### Бэкенд

`GET /api/v1/auth/me` кладёт в `org_branding` ещё одно поле:

```python
"menu_visibility": org_settings.get("menu_visibility") or {},
```

`or {}` вместо `.get(..., {})` — потому что в настройках может лежать `null`
от прежних сохранений, и он должен читаться как «карты нет», а не приезжать
на клиент как `null`.

Права на запись не трогаются: `PUT /admin/organizations/{org_id}` остаётся
за администратором.

### Фронтенд

`OrgBranding` получает необязательное поле
`menu_visibility?: Record<string, boolean>`. Необязательное осознанно: во время
выката новый фронтенд некоторое время разговаривает со старым бэкендом, и
обязательное поле уронило бы меню на `undefined[key]`. Чтение идёт через `?.`.

Боковое меню теряет свой `useState` и `useEffect` с запросом настроек;
`isMenuVisible` читает карту из хранилища:

```ts
const isMenuVisible = (key: string) => branding.menu_visibility?.[key] !== false;
```

Умолчание «показывать» сохраняется на всех трёх путях: карты нет, поле пустое,
ключа в карте нет.

Побочный выигрыш: страница настроек уже вызывает `fetchUser()` после
сохранения — значит меню администратора обновляется сразу, без перезагрузки
(US3), чего сегодня не происходит.

### Тесты

Три теста в `backend/tests/test_auth.py`, рядом с остальными про `/auth/me`:

1. **Положительный контроль.** Школа спрятала `gradebook` — преподаватель
   этой школы получает `menu_visibility == {"gradebook": False}`. Падает
   на текущем коде: поля нет.
2. **Изоляция.** Та же спрятанная настройка у школы A — преподаватель школы B
   получает пустую карту. Без первого теста этот зеленел бы и на пустом ответе.
3. **Умолчание.** Школа ничего не настраивала — карта пустая, не `null`.

Тесты живут в `test_auth.py`, а не в `test_cross_org_isolation.py`: там речь
про доступ к чужому объекту по его идентификатору, здесь идентификатора
в запросе нет вовсе. Держать положительный контроль и изоляцию рядом важнее,
чем раскладывать по файлам.
