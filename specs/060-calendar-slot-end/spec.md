# Занятие приходило в календарь без времени окончания

**Дата**: 2026-08-23 · **Ветка**: `fix/calendar-slot-end` · **Статус**: разобрано

## Что происходит

Проверяя в проде свежую правку `specs/054` (занятия из недельного шаблона
попадают в календарь), я запросил окно и получил 21 занятие — всё как задумано.
С одной оговоркой:

```json
{ "start_time": "2026-08-17T09:00:00", "end_time": null, "source": "lesson" }
```

Время окончания у слота есть — оно и в расписании, и в карточке группы. В
календарь оно не доехало.

## Причина

Строка моя же, из `specs/054`:

```python
"start_time": when.isoformat(),
"end_time": None,
```

Заглушка осталась с того черновика, где слот раскрывался в отметку на дне.
Соседняя запись — дедлайн задания — тоже отдаёт `None`, и это правильно: срок
сдачи есть миг, а не отрезок. Занятие же длится полтора часа, и календарь без
конца рисует его точкой: длительности не видно, накладка со следующим занятием
не видна.

## Решение

`_slot_end` собирает окончание из того же слота, на дне его начала. Формат тот
же ISO-8601 без пояса, что и у начала — календарь получает отрезок.

Слот без внятного `end_time` по-прежнему даёт `None`: лучше точка, чем
выдуманная длительность.

## Проверка

`backend/tests/test_calendar_lessons.py` — занятие вторника 17:00 приходит с
окончанием 18:30. Утверждение падает на коде до правки: там стоял `None`.

## Чему учит

Правку `specs/054` я закрыл зелёными тестами и не посмотрел на ответ живого
сервера. Тесты спрашивали, появилось ли занятие вообще, — про его конец не
спрашивал никто. Нашлось через полчаса после выкладки, потому что я открыл прод
и прочитал JSON целиком, а не глазами по нужному полю.
