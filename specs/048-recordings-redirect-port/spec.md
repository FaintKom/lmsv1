# Записи занятий недоступны: редирект уводит браузер на порт 8443

**Дата**: 2026-08-23 · **Ветка**: `fix/walkthrough-nginx-recordings-redirect` · **Статус**: разобрано

## Что происходит

Страница live-уроков пуста у всех ролей — и у ученика (`/live`), и у учителя
(`/admin/live`). Вместо списка или честного «пока пусто» там одно многоточие.
Найдено ручным сквозным прогоном 2026-08-23 (Н-20 и Н-21 в
`tasks/walkthrough-2026-08-23-full-path.md`).

Запрос списка записей не доходит до сервера:

```
GET https://grasslms.online/api/v1/recordings
→ 301 Moved Permanently
  Location: https://grasslms.online:8443/api/v1/recordings/
```

Порт 8443 снаружи закрыт. Браузер честно идёт по указанному адресу и виснет:
запрос остаётся в `pending`, `fetch` завершается `Failed to fetch`. Компонент,
который ждёт эти данные, так и остаётся с многоточием.

## Почему 301 вообще появляется

Это документированное поведение nginx, а не ошибка конфигурации. Из описания
директивы `location`: если префикс заканчивается слэшем и запрос обрабатывается
`proxy_pass`, то на запрос **без** завершающего слэша nginx отвечает постоянным
редиректом на адрес со слэшем.

Такой блок у нас есть — записям нужен свой лимит размера тела:

```nginx
location /api/v1/recordings/ {
    proxy_pass $backend_upstream;
    client_max_body_size 320M;
}
```

Маршрут же объявлен без слэша — `@router.get("")` при префиксе
`/api/v1/recordings`, и клиент зовёт именно его. Отсюда редирект.

Сам по себе редирект безвреден: адрес со слэшем работает и отдаёт 200 —
проверено авторизованным запросом из браузера. Ломает дело **порт в адресе**.
Редирект nginx по умолчанию абсолютный и собирается из
`$scheme://$host:$server_port`, а этот сервер слушает `127.0.0.1:8443`: порт 443
принадлежит потоковому листенеру в `stream.d`, который разбирает TLS по SNI.
Внутренний порт и уезжает наружу.

## Решение

Одна строка на уровне сервера:

```nginx
absolute_redirect off;
```

Редиректы становятся относительными — `Location: /api/v1/recordings/`, — и
браузер разрешает их относительно публичного адреса. Порт исчезает из ответа
вместе с абсолютным адресом.

Правка лечит класс, а не случай: любой другой редирект этого сервера перестаёт
выдавать внутренний порт наружу.

**Почему не точное совпадение.** Документация предлагает второй путь — добавить
`location = /api/v1/recordings`. Это убрало бы лишний переход, но ценой копии
восьми строк проксирования, которые дальше пришлось бы держать в согласии
руками. Лишний переход стоит одного запроса; расхождение двух блоков обходится
дороже.

## Проверка

Автотеста нет намеренно: nginx в CI не поднимается, а стенд
`docker-compose.qa.yml` ходит в бэкенд напрямую, без прокси. Тест там прошёл бы
и на сломанном конфиге, то есть был бы неспособен упасть. Проверка ручная, после
деплоя:

```bash
curl -s -o /dev/null -D - https://grasslms.online/api/v1/recordings | head -6
```

Ожидается либо `401` без редиректа, либо `301` с относительным
`Location: /api/v1/recordings/`. Абсолютный адрес с портом 8443 — признак, что
правка не доехала.

Дополнительно: страницы `/live` и `/admin/live` перестают быть многоточием.

## Что осталось за рамками

`/live` рисует `<p>…</p>` вместо честного пустого состояния — это отдельная
находка (Н-20) и отдельная правка: экран должен называть себя даже тогда, когда
данные приходят пустыми.
