# Feature Specification: В примере окружения нет переменной, без которой dev не работает

**Feature Branch**: `chore/env-example-backend-url`

**Created**: 2026-08-22

**Status**: Draft

**Input**: `frontend/.env.local.example` перечисляет `NEXT_PUBLIC_API_URL`, а
dev-серверу нужен `BACKEND_URL`. Кто копирует пример, получает 404 на каждый
запрос к API и ни одной подсказки почему. Замечено 2026-08-22.

## Что происходит сейчас

Пример окружения фронтенда состоит из двух строк:

```
NEXT_PUBLIC_API_URL=http://localhost:8000
NEXT_PUBLIC_BYBIT_USDT_ADDRESS=
```

Человек копирует его в `.env.local`, поднимает бэкенд на :8000, запускает
`npm run dev` — и не может залогиниться. Каждый запрос к `/api/v1/*` отвечает
404. Отвечает не бэкенд: 404 приходит от самого Next, который такого маршрута
у себя не знает.

## Почему так

Две переменные с похожими именами работают в разное время и в разных местах.

`api-client` ходит по относительному адресу — `baseURL: "/api/v1"` прошит в
[`api-client.ts`](frontend/src/lib/api-client.ts:14) и из окружения не читается.
Значит запрос уходит на тот же порт, где живёт фронт, и кто-то должен
перенаправить его на бэкенд. В проде это делает nginx. В `next dev` —
`rewrites()` в [`next.config.ts`](frontend/next.config.ts:20), а он читает
`process.env.BACKEND_URL` и **возвращает пустой список, если переменной нет**.
Ни ошибки, ни предупреждения при старте: прокси просто не появляется, и Next
отвечает на `/api/v1/*` своим обычным 404.

`NEXT_PUBLIC_API_URL` — переменная времени сборки для образов QA и прода. Она
приезжает через build args в [`Dockerfile.qa`](frontend/Dockerfile.qa:18) и
`docker-compose.qa.yml`. В `next dev` она меняет ровно одну вещь: ссылку на
скачивание файла работы в review-странице заданий
([page.tsx:186](frontend/src/app/(admin)/admin/assignments/%5Bid%5D/review/page.tsx:186)).
Больше её в `frontend/src` не читает никто.

Итог: пример задаёт переменную, которая влияет на одну ссылку, и молчит про ту,
без которой не работает ни один запрос.

## Где ещё лежит та же ошибка

Правильный ответ в репозитории есть — в [`tasks/lessons.md`](tasks/lessons.md:24),
в [`quickstart`](specs/034-mobile-tabs-i18n/quickstart.md:35) спеки 034, в
`.github/workflows/ci.yml` и в [`frontend/CLAUDE.md`](frontend/CLAUDE.md:94), где
про `BACKEND_URL` сказано прямо. До файлов, которые копируют руками, он не дошёл:

| Файл | Что говорит |
|---|---|
| [`frontend/.env.local.example`](frontend/.env.local.example) | только `NEXT_PUBLIC_API_URL` |
| [`docs/DEVELOPMENT.md:41`](docs/DEVELOPMENT.md:41) | шаг установки пишет в `.env.local` `NEXT_PUBLIC_API_URL` |
| [`docs/DEVELOPMENT.md:206`](docs/DEVELOPMENT.md:206) | раздел «фронтенд не может достучаться до backend» присылает проверять `NEXT_PUBLIC_API_URL` |
| [`frontend/CLAUDE.md:174`](frontend/CLAUDE.md:174) | «Минимум для `.env.local`» — `NEXT_PUBLIC_API_URL` |
| [`docs/API_REFERENCE.md:8`](docs/API_REFERENCE.md:8) | «Фронт обращается через `NEXT_PUBLIC_API_URL`» |

Два места стоят отдельно. Раздел 206 в `DEVELOPMENT.md` — это ровно тот симптом,
с которым туда придут, и он уводит в сторону. А `frontend/CLAUDE.md`
противоречит сам себе: на строке 94 сказано «в dev — rewrite через
`BACKEND_URL`», на строке 174 — что минимума хватает без него. Этот файл Claude
Code загружает сам, поэтому ошибку читает каждый следующий агент.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Скопировал пример, и фронт видит бэкенд (P1)

Человек впервые поднимает проект. Копирует `.env.local.example` в `.env.local`,
ничего в нём не дописывая, запускает бэкенд и `npm run dev` — и логинится.

**Why this priority**: единственная причина правки. Пример окружения существует
ради того, чтобы его скопировали и всё заработало.

**Independent Test**: `cp frontend/.env.local.example frontend/.env.local`,
поднять бэкенд на :8000, `npm run dev`, открыть страницу входа и войти. Запрос
`POST /api/v1/auth/login` отвечает 200, а не 404.

**Acceptance Scenarios**:

1. **Given** `.env.local` — дословная копия примера, **When** запущены бэкенд и
   `next dev`, **Then** запросы к `/api/v1/*` доходят до бэкенда.
2. **Given** тот же файл, **When** человек читает его сверху вниз, **Then** из
   комментария видно, какая переменная нужна dev-серверу, а какая запекается в
   образ при сборке.

---

### User Story 2 — Документация не уводит в сторону (P2)

Человек не скопировал пример, а пошёл по `docs/DEVELOPMENT.md`. Или уже упёрся в
404 и открыл раздел про то, что фронт не достучался до бэкенда.

**Why this priority**: инструкция и раздел про неисправность ведут в ту же яму,
что и пример. Починить один пример и оставить инструкцию — оставить ловушку
взведённой.

**Independent Test**: пройти шаги установки из `docs/DEVELOPMENT.md` буквально,
не заглядывая никуда ещё, и залогиниться.

**Acceptance Scenarios**:

1. **Given** человек выполняет шаг 5 установки как написано, **When** он
   запускает `npm run dev`, **Then** фронт видит бэкенд.
2. **Given** человек получил 404 и открыл раздел «фронтенд не может достучаться
   до backend», **When** он делает то, что там написано, **Then** причина
   названа верно.

---

### User Story 3 — Следующий агент не повторит ошибку (P3)

Claude Code загружает `frontend/CLAUDE.md` сам. Агент, который поднимает
dev-сервер, должен прочитать там правду с первого раза.

**Why this priority**: цена ошибки здесь повторяется на каждой сессии, но
починка — та же строка, что и в остальных файлах.

**Independent Test**: прочитать в `frontend/CLAUDE.md` раздел про запуск и
раздел про API-клиент подряд. Они не противоречат друг другу.

**Acceptance Scenarios**:

1. **Given** агент читает «Минимум для `.env.local`», **When** он выполняет
   написанное, **Then** dev-сервер проксирует запросы на бэкенд.

### Edge Cases

- Заданы обе переменные сразу — так и будет, потому что вторая в примере уже
  есть и остаётся со своим значением. Ничего не ломается: `BACKEND_URL`
  поднимает прокси, `NEXT_PUBLIC_API_URL` делает ссылку на файл работы
  абсолютной, и по ней с :3000 на :8000 куки доезжают (порт не меняет site).
- Бэкенд слушает не :8000. Значение в примере — умолчание, а не догма; из
  комментария должно быть понятно, что это адрес бэкенда, и его меняют.
- Сборка образов. Правка трогает только пример и документацию, поэтому
  `docker-compose.qa.yml`, `Dockerfile.qa` и CI продолжают передавать
  переменные так же, как передавали.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `frontend/.env.local.example` MUST содержать `BACKEND_URL` со
  значением по умолчанию `http://localhost:8000`.
- **FR-002**: Файл MUST объяснять разницу между двумя переменными: `BACKEND_URL`
  — куда dev-сервер перенаправляет запросы, `NEXT_PUBLIC_API_URL` — что
  запекается в образ при сборке. Объяснение MUST умещаться в комментарий и не
  отсылать к другому файлу.
- **FR-003**: Шаг установки фронтенда в `docs/DEVELOPMENT.md` MUST создавать
  `.env.local`, которого достаточно для работы.
- **FR-004**: Раздел `docs/DEVELOPMENT.md` про то, что фронт не достучался до
  бэкенда, MUST называть `BACKEND_URL` первой причиной.
- **FR-005**: `frontend/CLAUDE.md` MUST перестать противоречить сам себе:
  «минимум для `.env.local`» MUST совпадать с тем, что сказано про `baseURL` и
  rewrite.
- **FR-006**: `docs/API_REFERENCE.md` MUST перестать утверждать, что фронт
  обращается к API через `NEXT_PUBLIC_API_URL`.
- **FR-007**: Правка MUST не менять поведение кода. Ни `next.config.ts`, ни
  `api-client.ts`, ни compose-файлы, ни Dockerfile'ы не трогаются.

### Key Entities

- **`BACKEND_URL`**: адрес бэкенда для `rewrites()` в `next.config.ts`.
  Читается при старте `next dev` и при `next build`. Без неё прокси нет.
- **`NEXT_PUBLIC_API_URL`**: префикс, запекаемый в бандл при сборке. В
  `frontend/src` читается в одном месте — ссылка на скачивание файла работы.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Дословная копия `.env.local.example` даёт рабочий dev-фронт:
  логин проходит, запросы к `/api/v1/*` отвечают не 404. Проверено запуском.
- **SC-002**: Ни один из пяти перечисленных файлов не называет
  `NEXT_PUBLIC_API_URL` как то, что нужно задать для локальной разработки.
- **SC-003**: Диагностика той же поломки занимает чтение одного файла — того, в
  который человек уже смотрит, — вместо перезапуска dev-сервера.
- **SC-004**: `git diff` не содержит изменений в файлах с кодом и сборкой.

## Assumptions

- Бэкенд локально слушает :8000 — так написано во всех инструкциях репозитория
  и так задано в CI.
- `NEXT_PUBLIC_API_URL` в примере остаётся: она нужна для сборки QA-образов, и
  убирать её — отдельное решение с другой ценой. Правка объясняет её, а не
  удаляет.
- Пустое значение `NEXT_PUBLIC_BYBIT_USDT_ADDRESS` — намеренное, оно прячет блок
  криптодоната. Не трогается.

## Out of scope

- Заставить `next.config.ts` шуметь при отсутствии `BACKEND_URL`. Это починило
  бы причину, а не документацию, но меняет поведение сборки: CI и оба
  compose-стека задают переменную, а прод собирается без неё намеренно —
  там проксирует nginx. Отдельная спека, если тишина при старте будет мешать
  и дальше.
- Прошитый `baseURL` и единственный потребитель `NEXT_PUBLIC_API_URL`. Свести
  две переменные к одной можно, но это правка кода и сборки, а здесь чинится
  инструкция.
