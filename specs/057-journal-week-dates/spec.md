# Недельная сетка расписания уезжает на день за вызов

**Дата**: 2026-08-23 · **Ветка**: `fix/walkthrough-week-dates` · **Статус**: разобрано

## Что происходит

Ручной прогон 2026-08-23 (Н-06 в `tasks/walkthrough-2026-08-23-full-path.md`)
снял с экрана `/admin/journal?tab=schedule` три странности сразу — дело было в
воскресенье 23 августа:

- сетка открылась на окне **Сб 15.08 – Чт 20.08**: сегодняшнего дня в нём нет;
- «следующая неделя» дала **Пт 21.08 – Ср 26.08**, затем **Чт 27.08 – Вт
  01.09** — шаг шесть дней, окно ползёт;
- заголовок расходится с колонками ровно на день: «Aug 22 – Aug 26» над
  колонками 21.08–26.08.

Шесть колонок — не ошибка: школьная неделя здесь понедельник–суббота,
`WEEKDAY_KEYS = [0..5]`. Ошибка в датах.

## Причина одна на все три симптома

```ts
function shiftISO(iso: string, days: number): string {
  const d = new Date(iso + "T00:00:00");   // локальная полночь
  d.setDate(d.getDate() + days);
  return d.toISOString().slice(0, 10);      // ...напечатана как UTC
}
```

`new Date("2026-08-24T00:00:00")` — полночь **по месту читателя**. `toISOString`
печатает тот же миг в UTC, и восточнее Гринвича это предыдущий день: в UTC+3
полночь 24-го — 21:00 23-го. Каждый вызов теряет сутки.

Отсюда складывается всё:

- `mondayOf(today)` теряет день — понедельник становится воскресеньем;
- `shiftISO(weekStart, d)` при отрисовке колонок теряет ещё один — суббота;
- `shiftISO(weekStart, ±7)` теряет день на каждом переходе — шаг ±6;
- заголовок и колонки проходят разное число таких превращений — отсюда
  расхождение на день.

Календарный день — не миг времени, и гонять его через UTC нельзя.

## Решение

Три функции переехали в `frontend/src/lib/date-iso.ts` и печатают дату
локально, через `getFullYear` / `getMonth` / `getDate`. В журнале не осталось ни
одного `toISOString`.

Правка чинит не только доску расписания: `todayISO` и `shiftISO` питают ещё и
вкладки «Today» и «Register» — там же переключение дня стрелками.

## Проверка

`frontend/src/lib/date-iso.test.ts`: сдвиг на ноль дней ничего не меняет, сдвиг
на неделю даёт тот же день недели, шаг через границу месяца, поиск понедельника
из любого дня его недели.

**Честно о красноте.** CI гоняет тесты в `TZ=UTC`, а в UTC старый код эти
утверждения тоже выполнял: воспроизвести первоначальный сбой в CI можно только
принудительной сменой пояса на весь прогон, чего я делать не стал. Красное
доказательство здесь — замер с экрана в браузере UTC+3, приведённый выше:
суббота вместо понедельника и шаг в шесть дней. Тест закрепляет контракт и
упадёт, если календарный день снова поедет через UTC там, где это видно.

Ручная проверка после деплоя: открыть журнал в воскресенье и увидеть неделю, в
которой есть сегодня, а «следующая неделя» перещёлкивает ровно на семь дней.
