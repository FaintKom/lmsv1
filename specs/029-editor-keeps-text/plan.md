# Implementation Plan: Редактор не теряет текст урока

**Branch**: `fix/text-block-keeps-string-body` | **Date**: 2026-08-20 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/029-editor-keeps-text/spec.md`

## Summary

Текстовый блок открывается тем редактором, который подходит его телу, а не
тем, который удобен коду. Тело-объект — TipTap, как и раньше. Непустое
тело-строка — правка исходного текста с сохранением формата. Пустое тело —
TipTap, потому что это новый блок.

Развилка переезжает из JSX в чистую функцию `textBlockEditor(body)` рядом с
`exercise-block-state.ts`; тесты работают с ней, а не с компонентом.

## Technical Context

**Language/Version**: TypeScript 5 strict, React 19, Next.js 16 (App Router)

**Primary Dependencies**: TipTap 3 (`BlockEditor`), `ContentRenderer` — обе уже
в файле, новых зависимостей нет

**Storage**: не затрагивается. Блоки лежат в `lessons.content` (JSONB), схема
и миграции не меняются

**Testing**: Vitest (`frontend/src/**/*.test.ts`), плюс проверка в браузере на
реальном уроке

**Target Platform**: браузер, страница `/admin/lessons/[lessonId]/edit`

**Project Type**: web, изменение только во фронтенде

**Performance Goals**: не применимо — развилка считается один раз на блок при
отрисовке

**Constraints**: правка не должна менять `format`; сборка не растёт, новых
пакетов нет

**Scale/Scope**: 63 текстовых блока в 60 уроках прода; один компонент, одна
новая функция, один тест-файл

## Design

### Чистая функция

```ts
export type TextBlockEditor =
  | { kind: "rich"; content: Record<string, unknown> | null }
  | { kind: "source"; text: string };

export function textBlockEditor(
  body: string | Record<string, unknown> | undefined,
): TextBlockEditor
```

Решает **тело**, а не ярлык `format`:

| Тело | Результат | Почему |
|---|---|---|
| объект | `rich`, content = тело | документ TipTap, каким и был |
| непустая строка | `source`, text = тело | TipTap не удержит `aside` и `table`; правим как есть |
| `""`, пробелы, `undefined` | `rich`, content = `null` | новый блок: `addBlock` создаёт `body: ""`, `format: "tiptap"` — терять нечего |

`format` в аргументы не входит намеренно. Строку нельзя отдать в
`BlockEditor` независимо от того, что написано в ярлыке, а объект — можно.
Ярлык бывает пустым и бывает лживым; тело — нет.

### Что делает компонент

- `rich` → `<BlockEditor content={…} onChange={json => onUpdate({ body: json, format: "tiptap" })} />`
  — как сегодня.
- `source` → `<textarea value={text} onChange={e => onUpdate({ body: e.target.value })} />`.
  **В патче нет поля `format`** — это и есть FR-003: не «сохраняем прежний
  формат», а вовсе его не трогаем. Блок с пустым `format` не получит
  выдуманного.

Подпись над `source` объясняет учителю, почему здесь исходный текст, и
напоминает про переключатель предпросмотра. Ключ добавляется во все шесть
локалей — иначе падает `translations.test.ts`.

## Phase 0: Research

Выполнена внутри спеки, отдельного файла нет. Итог, на котором стоит план:

- **Решение**: тело-строка правится как строка, формат не переписывается.
- **Обоснование**: схема редактора (`block-editor.tsx:270`) не знает `aside`,
  `div` и `table`; расширения таблиц в проекте нет вовсе. Сиды пишут именно их
  (`scripts/seed_demo_org.py`). Конверсия при первом нажатии клавиши потеряла
  бы таблицу целиком и рамку примера — тот же дефект, только тише.
- **Отвергнуто: отдать HTML в TipTap и писать `format: "tiptap"`** — чинит
  пустое поле и оставляет потерю данных.
- **Отвергнуто: доставить `@tiptap/extension-table` и прочее недостающее** —
  не закрывает `aside` с инлайновыми стилями и `<script>`-виджеты, добавляет
  вес сборке, которая собирается на проде под лимитом памяти.
- **Отвергнуто: определять на лету, конвертируется ли содержимое без потерь** —
  тогда догадка о содержимом решала бы, стирать его или нет. Правило, которое
  смотрит только на тип тела, предсказуемо и проверяемо.
