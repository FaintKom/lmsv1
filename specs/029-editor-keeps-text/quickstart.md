# Quickstart: как проверить, что редактор перестал терять текст

## Красный тест до правки

Тест ставится первым и обязан упасть на сегодняшнем коде — иначе он ничего не
доказывает (конституция, принцип II).

```bash
cd frontend && npx vitest run "src/app/(admin)/admin/lessons/[lessonId]/edit/text-block-editor.test.ts"
```

Красным должен быть случай «непустое тело-строка»: сегодня развилка
(`page.tsx:882`) отдаёт в редактор `null`, и текста в нём нет.

Тот же прогон становится зелёным после появления `textBlockEditor()`.

## Весь фронтовый набор

```bash
cd frontend && npm test
```

Сюда входит парность шести локалей (`translations.test.ts`) — она упадёт, если
ключ подписи добавлен не во все словари.

```bash
cd frontend && npx tsc --noEmit
```

## Проверка в браузере на реальном уроке

Нужен урок, у которого тело текстового блока — строка. В проде таких 63;
локально их даёт сид демо-организации.

1. Поднять фронтенд: `cd frontend && npm run dev` (нужен `.env.local`, в git
   его нет).
2. Войти учителем, открыть курс «Math 7: Algebra Foundations», урок
   «Solving linear equations», далее «Редактировать».
3. **До правки** — текстовый блок пуст. Это и есть дефект: 1828 символов HTML
   лежат в базе и не видны на экране.
4. **После правки** — в блоке виден исходный текст, начиная с
   `<h2>Goal: get $x$ alone</h2>`, и подпись, почему он показан исходным.
5. Переключить предпросмотр — блок собирается как раньше: заголовок, формулы,
   рамки примеров.

## Что смотреть при самой правке

Сетевой запрос сохранения урока должен нести:

- `body` — строку, а не объект;
- `format` — тем же, каким пришёл: `html` остаётся `html`;
- изменённый текст на месте.

Если в теле запроса оказался объект `{"type":"doc",…}`, правка не работает, и
блок теряет содержимое ровно так же, как до неё.

## Чего эта проверка не покрывает

Существующее содержимое **не конвертируется** в TipTap: миграция в работу не
входит. Богатый редактор для старых блоков остаётся недоступен — это известное
следствие, а не недосмотр (см. Assumptions в spec.md).
