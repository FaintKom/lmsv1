# Массовый импорт заводит учеников, в которых нельзя войти

**Дата**: 2026-08-23 · **Ветка**: `fix/walkthrough-bulk-import-password` · **Статус**: разобрано

## Что происходит

Школа импортирует класс, экран отвечает «3 created, 0 skipped, 0 errors» — и ни
один из троих войти не может. Найдено ручным сквозным прогоном 2026-08-23 (Н-03
в `tasks/walkthrough-2026-08-23-full-path.md`) на живых данных.

У экрана два режима. «Create & Enroll in Course» показывает поле «Default
password» с заполненным значением. «Import Students Only» — тот же импорт, тот
же CSV — поля не показывает вовсе:

```tsx
{mode === "enroll" && ( … поле пароля … )}
```

Сервер о таком параметре и не знал: строка без пароля получала случайный,
который хешируется и забывается —

```python
if not password:
    password = _generate_password()
```

В ответе только счётчики. Пароль не показан, не выгружен, письмом не отправлен.
Единственный путь дальше — сброс пароля поштучно, и то если у ученика есть
почтовый ящик.

Предпросмотр честно писал «random» в колонке пароля, но человек читает это как
«система придумает», а не как «доступа не будет».

## Решение

Поле пароля по умолчанию показывается в обоих режимах — это один и тот же
импорт. Сервер принимает `default_password` и применяет его к строкам без
пароля; случайный остаётся крайним случаем, когда не задано ни то ни другое.

Заодно сервер держит обещание экрана про восемь символов: короче — 400.

Порядок приоритета: пароль в строке CSV → пароль по умолчанию → случайный.
Первый нужен школам, которые ведут пароли у себя; второй — обычному случаю
«завести класс и раздать один временный».

**Чего намеренно не сделано.** Показывать сгенерированные пароли в ответе —
соблазнительно и неправильно: они осядут в истории браузера, в логах прокси и в
чужом скриншоте. Правильная альтернатива случайному паролю — приглашение по
ссылке, но это отдельная работа: почта, сроки жизни ссылок, повторная отправка.

## Проверка

`backend/tests/test_bulk_import_password.py`:

- строка без пароля получает пароль по умолчанию — и ученик **входит** им;
- слишком короткий пароль по умолчанию отклонён с 400;
- пароль в строке CSV сильнее пароля по умолчанию.

Первые два написаны до правки и проверены красными. Соседний
`test_child_safety.py` (согласие родителей на обоих массовых обработчиках)
продолжает проходить.
