# Tasks: Из чего состоит урок — видно на странице курса

**Input**: Design documents from `/specs/037-course-lesson-elements/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/ui.md, quickstart.md

**Tests**: тесты обязательны и пишутся первыми — принцип II конституции. Каждый
тест должен падать на сегодняшнем коде; падение показывается в теле PR.

**Organization**: задачи сгруппированы по историям из спеки, чтобы каждую можно
было закончить и проверить отдельно.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: можно делать параллельно — разные файлы, нет незакрытых зависимостей
- **[Story]**: US1 (список), US2 (ссылки), US3 (добавление), US4 (строка урока)

## Path Conventions

Веб-приложение; правки только во `frontend/`. Пути даны от корня репозитория.
Сокращение `COURSE_EDIT` = `frontend/src/app/(admin)/admin/courses/[courseId]/edit`,
`LESSON_EDIT` = `frontend/src/app/(admin)/admin/lessons/[lessonId]/edit`.

## Implementation Strategy

### MVP

Phase 1 → Phase 2 → Phase 3 (US1). На этом состав урока уже виден со страницы
курса — самостоятельная польза, которую можно показать и выкатить.

### Дальше по одному

1. US2 — ссылки на правку.
2. US3 — добавление задания.
3. US4 — разведение раскрытия и перехода.

Каждая история заканчивается зелёным прогоном и может уехать в прод отдельно.
