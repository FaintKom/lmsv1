# Implementation Plan: Из чего состоит урок — видно на странице курса

**Branch**: `feat/course-lesson-elements` | **Date**: 2026-08-21 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/037-course-lesson-elements/spec.md`

## Summary

Строка урока на странице курса раскрывается в список её элементов, у каждого —
ссылка на правку в новой вкладке, а в конце каждой страницы урока — добавление
задания.

Состав урока уже лежит в том же поле, из которого считается сводка, поэтому
список рисуется без запроса. Один запрос уходит при раскрытии — за названиями
заданий; названия работ берутся поштучно, потому что их в уроках единицы.

Разбор содержимого не переписывается: `extractPages` из
`lib/lessons/lesson-pages.ts` уже приводит все три поколения формата к
страницам с блоками, и список строится поверх него. Создание задания уходит в
общий модуль, чтобы `specs/030` потом менял одно место, а не два.

## Technical Context

**Language/Version**: TypeScript 5 strict, React 19, Next.js 16 (App Router)

**Primary Dependencies**: TanStack Query 5 (серверное состояние), обёртка
`lib/api-client`, дизайн-токены Lively, `useTranslation` (шесть локалей)

**Storage**: не трогаем. Содержимое урока — поле `content` урока; задания —
свои записи

**Testing**: Vitest + @testing-library/react, тесты рядом с кодом. Чистые
функции — юнит-тестами, разметка — рендер-тестами. Playwright не требуется

**Target Platform**: браузер, страница `/admin/courses/[courseId]/edit`

**Project Type**: веб-приложение, правка только во `frontend/`

**Performance Goals**: раскрытие урока — не более одного запроса за названиями
заданий этого урока; раскрытие соседних уроков не повторяет уже сделанные
запросы

**Constraints**: бэкенд не меняется; изоляция школ остаётся на существующих
фильтрах; i18n-храповик требует `useTranslation` в каждом новом `.tsx`; новых
предупреждений ESLint не добавляем

**Scale/Scope**: курс до ~40 уроков на странице; урок до ~20 блоков; 26 типов
заданий в пяти группах

## Constitution Check

*GATE: пройден до Phase 0, перепроверен после Phase 1.*

| Принцип | Как соблюдается |
|---|---|
| **I. Изоляция школ** | Новых эндпоинтов нет. `by-lesson` фильтрует по `org_id` читателя (`exercises/service.py:210`), чтение одного задания отдаёт чужое как 404. Список рисуется из урока, который сам пришёл проверенным запросом. Новая поверхность не добавляет ни одного пути к чужим данным. |
| **II. Тест, способный упасть** | Сборка списка и вывод имени блока — чистые функции, их тесты падают на сегодняшнем коде (функций нет). Рендер-тест раскрытия проверяет, что до раскрытия запроса нет, а после — есть: он падает, если запрос уедет при монтировании. |
| **III. Судья ответа — сервер** | Проверки ответов не касается. |
| **IV. Продукт и документация об одном** | Спека, план и задачи в одной папке; шесть локалей получают ключи в одной правке. |
| **V. Наименьшее изменение** | Ни одного нового эндпоинта, ни одной новой модели. Разбор страниц переиспользуется. Единственное изменение вне страницы курса — якорь `?block=` в редакторе урока, без которого FR-004 невыполним. |

Нарушений нет, «Complexity Tracking» пуст.
