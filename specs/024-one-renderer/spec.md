# Feature Specification: One Renderer

**Feature Branch**: `feat/one-renderer`
**Created**: 2026-08-20
**Status**: Draft
**Input**: «Почему у нас вообще две версии рендера? Нужно оставить только новую и без старых данных и схем, все новое.»

## Что нашлось при разборе (факты, не догадки)

Версий рендера не две, а три, и вторая с третьей — разного качества.

1. **Живой путь ученика** — `V2ExerciseLive`: 16 типов, серверная
   проверка через `/exercises/{id}/check` и `/submit`.
2. **Старый рендерер** — `exercise-renderer.tsx` (1230 строк): все 26
   типов. Для 16 из них это мёртвый дубль; для оставшихся 10 (робот 2D,
   мир 3D, math interactive, code challenge, web editor, SCORM,
   step-by-step, флеш-карты, word search, file upload) — **единственная
   рабочая реализация**.
3. **Демо-вселенная** — `v2-runner.tsx` и TipTap-узел `v2Exercise`: ещё
   **33 виджета**, портированных из демо-файлов `q-*.jsx`. Их не
   использует никто, кроме этого раннера. Среди них — игрушечный робот
   6×6 с проверкой на клиенте, «SCORM» с фальшивым перелистыванием,
   мир 3D на SVG вместо Three.js и семнадцать математических шаблонов,
   дублирующих настоящие из `components/game/math/templates/`.

Ни один урок в проде не содержит вставленного узла `v2Exercise`
(проверено запросом к проду) — демо-вселенная не используется вообще.

## User Scenarios & Testing

### User Story 1 — Одно место, где решается, чем рисовать задание (P1)

Ученик, превью учителя и редактор урока получают задание через один
компонент. Ни одного второго пути, который может отстать.

**Acceptance**:
1. **Given** любой из 26 типов, **When** он открыт учеником, в превью
   каталога или в превью урока, **Then** рисует один и тот же компонент.
2. **Given** тип из живого списка, **Then** это его v2-виджет;
   **Given** остальные, **Then** их настоящая реализация с прежним
   подсчётом попыток.

### User Story 2 — Демо-вселенная удалена (P1)

33 неиспользуемых виджета, раннер и TipTap-узел удаляются вместе с
кнопкой в панели редактора.

**Acceptance**:
1. **Given** сборку после удаления, **Then** ни один импорт не ведёт в
   удалённые файлы, tsc и тесты зелёные.
2. **Given** редактор текста урока, **Then** кнопки вставки демо-задания
   больше нет.

### User Story 3 — Старый рендерер похудел до своей роли (P2)

Из `exercise-renderer.tsx` убираются ветки тех 16 типов, которые
рисует v2; остаётся только то, для чего он единственная реализация.

**Acceptance**:
1. **Given** тип из живого списка, **Then** в старом рендерере его
   ветки нет.
2. **Given** робот 2D, мир 3D, math interactive и остальные шесть,
   **Then** работают ровно как раньше.

### Edge Cases

- Урок, где задание вставлено «сиротой» (не блоком) — рисуется тем же
  единым компонентом.
- Легаси-уроки типов quiz/theory/interactive продолжают работать: они
  живут не в рендерере заданий, их черёд в этапе 9.

## Requirements

- **FR-001**: Один компонент решает, чем рисовать задание; все три
  места вызывают его.
- **FR-002**: Демо-виджеты, раннер и TipTap-узел удалены; сборка чиста.
- **FR-003**: Ветки живых типов удалены из старого рендерера.
- **FR-004**: Поведение ученика не меняется ни для одного из 26 типов.
- **FR-005**: Integrity model B не ослабляется: ответы по-прежнему не
  доходят до ученика, проверка серверная там, где была.

## Success Criteria

- **SC-001**: Ноль файлов, которые рисуют задание в обход единого
  компонента (проверяется тестом на маршрутизацию всех 26 типов).
- **SC-002**: Удалено ≥ 33 неиспользуемых виджета и ≥ 1200 строк
  дублирующего кода.
- **SC-003**: Все 26 типов открываются учеником и в превью без ошибок —
  та же проверка, что делалась вручную для превью.

## Assumptions

- Демо-виджеты никому не нужны: их не используют ни ученик, ни
  учитель, ни один урок в проде.
- Легаси-компоненты в `components/submissions/exercises/` пока
  остаются: их держит `interactive-taker` для старых уроков-«interactive».
  Уходят в этапе 9 вместе с самими уроками.
