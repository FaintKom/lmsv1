### Что параллелится, а что нет

Один файл диктует почти весь порядок. `sidebar.tsx` и `nav-tree.ts` правят
US1, US2, US3, US5 и US6 — они идут цепочкой. US4 живёт в своих страницах и
делается одновременно с чем угодно после Foundational.

```text
Setup → Foundational ─┬─→ US1 → US2 → US3 → US6 → US5 ─┐
                      └─→ US4 ────────────────────────┴─→ Polish
```

параллельны», и оба намеренные:

## Implementation Strategy

### MVP — только US1

1. Setup (T001–T002)
2. Foundational (T003–T005)
3. US1 (T006–T018)
4. **Остановиться и проверить**: сценарий 1 из quickstart под тремя ролями
5. Этого достаточно, чтобы показать: меню сворачивается, бренд школы на месте,
   выбор помнится, а страница `/cookies` перестала врать

### Дальше по одному

1. + US2 → меню перестаёт быть плоским
2. + US3 → прошедший урок и его запись наконец находятся, в том числе учеником
3. + US6 → Jitsi уходит
4. + US4 (параллельно) → настройки чужой школы достижимы
5. + US5 → поиск на своём месте

### Про слияние — важнее обычного

Слияние в `main` — это деплой, без ручного шага и без ревью между мержем и
продом. Миграция в ветке есть, но необратимого шага в ней нет: таблица пуста и
ни на что не ссылается, пользователей на платформе пока не появилось. Один PR.

Делить по границе историй — только если он станет неудобно большим для чтения.
Тогда мержить по одному, дожидаясь завершения предыдущего деплоя: два мержа в
одно окно оставляют прод на коммит позади.
