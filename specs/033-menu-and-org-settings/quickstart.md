# Quickstart: проверить, что меню и настройки работают

**Feature**: `specs/033-menu-and-org-settings`
**Date**: 2026-08-20

Как убедиться, что сделанное работает. Не описание реализации — только запуск
и наблюдение.

---

## Подготовка

```bash
cd frontend && npm install --legacy-peer-deps
```

`--legacy-peer-deps` обязателен, а не по вкусу: Sentry 9 не сходится с React 19
без него.

`.env.local` по умолчанию смотрит на **прод** (`https://grasslms.online`). Для
проверки против локального бэкенда его надо перенаправить — и вернуть обратно,
когда закончите.

Проверять нужно под тремя ролями: преподаватель, администратор школы,
суперадмин. У них разные меню, и половина требований — про роли.

---

## Быстрые проверки, которые ничего не запускают

```bash
cd frontend && npx tsc --noEmit
```

```bash
cd frontend && npm test -- translations
```

Второй ловит ключ, забытый в одной из шести локалей. Ключ, добавленный в пять
из шести, — это красный тест, а не мелочь.

```bash
cd frontend && npm test -- no-hardcoded-strings
```

Ратчет i18n: новый `.tsx` обязан звать `useTranslation()`. Список исключений
разрешено только сокращать.

## Сценарий 1 — меню сворачивается и помнит выбор

1. Запустить приложение и войти администратором.
2. Свернуть меню кнопкой. Ожидается: рельс, на нём логотип школы и её
   название, пункты — иконками.
3. Навести курсор на иконку. Ожидается: подсказка с названием пункта.
4. Убрать мышь, пройти по меню клавишей Tab. Ожидается: подсказка появляется и
   по фокусу тоже.
5. Перезагрузить страницу. Ожидается: меню осталось свёрнутым.
6. Перейти в раздел ученика, например `/profile`. Ожидается: меню свёрнуто и
   там.
7. Открыть инструменты разработчика → Application → Local Storage. Ожидается:
   ключ `sidebar-collapsed`, внутри `collapsed: true`.
8. Сверить с текстом на `/cookies`. Ожидается: описанное там и лежащее в
   хранилище — одно и то же (SC-010).

**Проверка бренда.** Задать школе свой `display_name` и `logo_url` на экране
настроек, затем свернуть меню и открыть страницу урока. Ожидается: и на
рельсе, и на верхней полосе урока — логотип школы, а не зелёная «g», и её
название, а не «GrassLMS».

**Проверка движения.** Включить в системе «уменьшить движение» и свернуть меню
снова. Ожидается: мгновенно, без перехода.

**Проверка на узком экране.** Сузить окно меньше 768 px. Ожидается: кнопки
сворачивания нет, меню работает выдвижной шторкой, как и раньше.

## Сценарий 2 — категории

1. Войти суперадмином. Ожидается: пять категорий и «Дашборд» отдельной строкой
   сверху; ни одного пункта вне этой раскладки.
2. Пересчитать пункты. Ожидается: 21 — на один меньше прежних 22: два пункта,
   «Онлайн-уроки» (Jitsi) и «Записи», заменены одним, «Живые уроки».
3. Открыть страницу внутри категории «Обучение», например `/admin/courses`.
   Ожидается: «Обучение» раскрыта, «Курсы» подсвечены.
4. Свернуть «Люди», перезагрузить. Ожидается: «Люди» остались свёрнутыми.
5. Пройти меню с клавиатуры. Ожидается: заголовок категории получает фокус
   раньше своих пунктов; пункты свёрнутой категории пропускаются.
6. Войти преподавателем. Ожидается: категории, где преподавателю нечего
   открыть, не показаны вовсе — ни заголовка, ни пустого места.
7. Войти учеником. Ожидается: меню плоское, без категорий.

**Сверка «ничего не потеряли» (SC-007).** Выписать пункты меню на `main` для
каждой из трёх ролей и сравнить со списком после правки. Разница обязана быть
только в одном месте: вместо «Онлайн-уроки» и «Записи» — «Живые уроки».

## Сценарий 3 — живой урок и его запись в одном месте

1. Провести живой урок: со страницы групп нажать «начать урок», записать
   короткий фрагмент, завершить.
2. Открыть `/admin/live`. Ожидается: урок в списке, сверху; при нём его
   запись.
3. Открыть запись. Ожидается: проигрывается.
4. Включить «поделиться с группой», выключить обратно. Ожидается: работает как
   на прежней странице записей.
5. Под преподавателем: кнопки удаления записи нет. Под администратором: есть и
   удаляет.
6. Найти запись, у которой нет урока. Ожидается: она в отдельной группе внизу,
   а не потеряна.
7. Открыть `/admin/recordings` напрямую. Ожидается: перебросило на
   `/admin/live`, не 404.
8. Открыть `/admin/meetings` напрямую. Ожидается: туда же.
9. Проверить меню: пунктов «Записи» и «Онлайн-уроки» нет, есть один — «Живые
   уроки».

**Про ученика — то, ради чего сценарий и нужен.** Войти учеником той группы,
которой поделились записью, открыть `/live`. Ожидается: урок в списке, запись
при нём, запись открывается. Сегодня ученик до неё дойти не может, хотя доступ
у него есть.

Затем войти учеником **другой** группы. Ожидается: этого урока в его списке
нет. Проверять только этот шаг нельзя — предыдущий и есть положительный
контроль, без которого «чужого урока не видно» зеленеет на пустом списке.

## Сценарий 4 — Jitsi ушёл, а похожее на него осталось

1. Запросить `/api/v1/meetings/` любым способом. Ожидается: 404.
2. Открыть `/meetings` и `/admin/meetings`. Ожидается: перебрасывает на
   списки живых уроков.
3. Проверить схему базы. Ожидается: таблицы `meetings` нет.
4. Применить миграцию второй раз. Ожидается: не падает.

Дальше — то, что ломается легче всего, потому что называется похоже:

5. Открыть журнал, кабинет с заданной ссылкой на видеокомнату. Ожидается:
   ссылка на месте и открывается. Это `rooms.meeting_url`, не Jitsi.
6. Открыть расписание, слот со ссылкой на встречу. Ожидается: работает.
7. Создать в календаре событие типа «встреча». Ожидается: создаётся.
   `EventType.meeting` — тип события, не Jitsi.
8. Открыть `/admin/integrations`. Ожидается: Zoom, Teams и Google Meet на
   месте — это другие интеграции.

## Сценарий 5 — настройки чужой школы

Нужны две организации. Вторую можно завести прямо на `/admin/organizations`
кнопкой создания.

1. Войти суперадмином, открыть `/admin/organizations`, выбрать **чужую** школу.
   Ожидается: экран её настроек.
2. Поменять название, цвет и спрятать какой-нибудь пункт меню. Сохранить.
   Ожидается: подтверждение.
3. Перезагрузить. Ожидается: значения остались изменёнными.
4. Вернуться к своей организации. Ожидается: её настройки не тронуты — это
   главное, ради чего сценарий и существует.
5. Выйти, войти администратором **своей** школы. Открыть
   `/admin/organizations`. Ожидается: в списке только своя школа.
6. Подставить в адрес id чужой школы напрямую. Ожидается: «не найдено», а не
   форма и не сообщение «нет доступа» — существование чужой школы не
   подтверждается.

**Про шаг 6 отдельно.** Проверять только его нельзя: «чужая школа отдаёт 404»
зеленеет и на несуществующем экране. Шаг 1 — положительный контроль, который
показывает, что экран вообще есть и работает. Без него шестой шаг ничего не
доказывает.

## Сценарий 6 — поиск переехал

1. Открыть меню под любой ролью. Ожидается: строки поиска нет.
2. Нажать `Ctrl+K`. Ожидается: ничего не происходит.
3. Открыть `/admin/courses`, ввести часть названия курса. Ожидается: список
   сузился.
4. Стереть введённое. Ожидается: вернулись все курсы.
5. Ввести заведомую бессмыслицу. Ожидается: сообщение «ничего не найдено», а
   не пустой экран.

## Сквозные проверки

```bash
cd frontend && npx playwright test e2e/journeys/navigation.spec.ts e2e/journeys/org-settings.spec.ts
```

Серверная часть — против настоящего PostgreSQL:

```bash
cd backend && pytest tests/ -q
```

Локально нужен поднятый стек и пароли ролей в переменных окружения:
`E2E_ADMIN_PASSWORD`, `E2E_TEACHER_PASSWORD`, `E2E_STUDENT_PASSWORD`. Значения
— в менеджере паролей владельца, в репозитории их нет и не должно быть.

Про запуск стека и его особенности — память `project_qa_system` и
`docs/TESTING.md`.

## Что проверять после слияния

**До слияния**, потому что миграция необратима: проверить дату свежайшей
резервной копии и число строк в таблице `meetings`. Оба запроса read-only.

Слияние в `main` — это деплой. Дождаться, пока пройдут и CI, и «Deploy to
Hetzner», затем открыть прод и повторить сценарии 1, 4 и 5. Первый показывает
рельс с настоящим брендом школы; четвёртый — что журнал и расписание пережили
уборку Jitsi; пятый — единственное место, где задача трогает права.
