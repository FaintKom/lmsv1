# Contracts: Меню короче, настройки школы достижимы

**Feature**: `specs/033-menu-and-org-settings`
**Date**: 2026-08-20

Новых эндпоинтов задача не заводит — только убирает. Три раздела: на что
интерфейс опирается из уже существующего, что он обещает пользователю сам и
что исчезает.

---

## 1. Серверные контракты — существующие, не меняются

### `GET /api/v1/admin/organizations`

Кто: любая роль администратора. Суперадмин получает все организации, остальные
— только свою. Это уже так работает, и на этом держится FR-025: администратору
школы в списке просто нечего открыть, кроме себя.

Ответ — массив объектов:

```json
[
  {
    "id": "<uuid>",
    "name": "Пример школы",
    "slug": "primer-shkoly",
    "is_active": true,
    "settings": { "display_name": "Пример школы", "primary_color": "#22c55e" },
    "created_at": "2026-01-15 10:30:00+00:00"
  }
]
```

### `GET /api/v1/admin/organizations/{org_id}`

Кто: суперадмин — любую организацию; администратор школы — только свою.
Чужая организация отдаёт **404, а не 403** — так требует принцип I
конституции, и так сервер уже отвечает (`NotFoundError`).

Ответ — один объект той же формы.

### `PUT /api/v1/admin/organizations/{org_id}`

Кто: те же права, та же реакция на чужую организацию.

Тело — все поля необязательны:

| Поле | Тип | Примечание |
|---|---|---|
| `name` | `string \| null` | Название организации |
| `is_active` | `boolean \| null` | Применяется **только** для суперадмина; администратору школы поле молча игнорируется |
| `settings` | `object \| null` | Сливается с существующим блоком, не заменяет его |

Пример запроса, который шлёт экран настроек:

```json
{
  "name": "Пример школы",
  "settings": {
    "display_name": "Пример школы",
    "logo_url": "",
    "primary_color": "#22c55e",
    "secondary_color": "#3b82f6",
    "menu_visibility": { "crm": false }
  }
}
```

**Слияние, а не замена** — важная деталь: сервер делает
`current.update(data.settings)`. Клиент может слать только изменившиеся ключи,
и настройки, о которых экран не знает, не сотрутся.

### `GET /api/v1/live-lessons`

Кто: любой аутентифицированный. **Разграничение делает сервер**, и оно уже
написано: ученик получает уроки своей группы через `StudentGroupMember`,
преподаватель — те, где он `teacher_id`, администратор и суперадмин — все в
своей организации. Последние 50, новые сверху. Параметров у запроса нет.

Отсюда следует контракт страницы: клиент **не** фильтрует список по роли
повторно и не пытается запросить больше пятидесяти.

### `GET /api/v1/recordings`

Кто: любой аутентифицированный. Сотрудник получает записи своей школы, ученик
— свои и те, у которых `shared_with_group = true`. Каждая запись несёт
`live_lesson_id`, по которому страница и раскладывает их по урокам; пустое
значение означает «записано вне урока».

### `PATCH /api/v1/recordings/{id}` и `DELETE /api/v1/recordings/{id}`

Переключение `shared_with_group` и удаление. Удаление сервер разрешает только
администратору и суперадмину — клиент лишь решает, показывать ли кнопку.

### Что интерфейс НЕ делает

Не проверяет права сам. Клиентская проверка «показывать ли кнопку» — это
оформление, а не контроль; судит сервер. Экран, открытый по прямой ссылке на
чужую организацию, обязан честно показать «не найдено» из ответа сервера, а не
угадывать заранее.

## 2. Контракты интерфейса

### 2.1. Боковое меню

| Элемент | Обещание |
|---|---|
| Кнопка сворачивания | Видна на экранах от 768 px. Имеет доступное имя. Переключает `collapsed` в сторе |
| Рельс (свёрнутое меню) | Показывает логотип школы и её название. Пункты — иконки. У каждой иконки есть `aria-label` и подсказка по наведению и по фокусу |
| Заголовок категории | `<button>` с `aria-expanded` и `aria-controls`, указывающим на `id` её списка |
| Список категории | `<ul>` с тем самым `id`. Скрыт, когда категория свёрнута |
| Активный пункт | `aria-current="page"`. Виден даже внутри свёрнутой категории |
| Пустая категория | Не отрисовывается вовсе — ни заголовка, ни списка |

Клавиатура: порядок обхода совпадает с порядком на экране. Заголовок категории
получает фокус до своих пунктов. Пункты свёрнутой категории выпадают из обхода
вместе со списком.

Движение: переход 150–300 мс на `transform`/`opacity`. При
`prefers-reduced-motion: reduce` перехода нет.

### 2.2. Список живых уроков

Адреса: `/admin/live` для сотрудника, `/live` для ученика. Разметка общая,
различает их только то, что отдаёт сервер.

| Элемент | Обещание |
|---|---|
| Строка урока | Дата, группа, преподаватель. Признак «идёт сейчас», если `status = active` |
| Записи урока | Показаны при своей строке. Несколько записей — показаны все, не последняя |
| Группа «без урока» | Отдельным блоком внизу; в ней записи, у которых `live_lesson_id` пуст |
| Пустой список | Сообщение с подсказкой, а не пустой экран |
| Ограничение сервера | Сервер отдаёт последние 50 уроков. Страница не притворяется, что показывает всё |

Действия над записью, обязаны остаться прежними (FR-015):

| Действие | Кто может |
|---|---|
| Посмотреть | все, кто видит запись; кнопка недоступна, пока `status ≠ ready` |
| Поделиться с группой | преподаватель, администратор, суперадмин |
| Удалить | **только** администратор и суперадмин |

Ученик получает тот же экран, но сервер отдаёт ему только уроки его группы и
записи, которыми поделились. Клиент своей фильтрации не добавляет.

### 2.3. Редиректы

Все три — временные (`permanent: false`), объявлены в `redirects()` файла
`frontend/next.config.ts`:

| Откуда | Куда |
|---|---|
| `/admin/recordings` | `/admin/live` |
| `/admin/meetings` | `/admin/live` |
| `/meetings` | `/live` |

Временные, а не постоянные: постоянный редирект браузер кэширует надолго, и
если адрес когда-нибудь вернётся, старые браузеры о нём не узнают. Две
существующие записи для снятого `/sat-practice` в том же блоке сделаны так же.

### 2.4. Экран настроек организации

Адрес: `/admin/organizations/{orgId}`.

| Состояние | Что видит пользователь |
|---|---|
| Загрузка | Индикатор ожидания |
| Успех | Форма с названием, логотипом, двумя цветами и переключателями видимости пунктов |
| Организация не найдена или чужая | Сообщение «не найдено» — одинаковое в обоих случаях, чтобы существование чужой школы не подтверждалось |
| Сохранено | Подтверждение; значения на форме совпадают с сохранёнными |

Форма — один компонент `org-settings-form.tsx` с обязательным пропом `orgId`.
Умолчания у `orgId` нет: именно молчаливое умолчание на `user.org_id` и делает
сегодняшний `/admin/settings` неспособным править чужую школу.

### 2.5. Фильтр курсов

Строка на `/admin/courses`. Сужает уже загруженный список по вхождению
подстроки в название, без учёта регистра. Пустая строка показывает всё. Когда
совпадений нет, на месте списка — сообщение, а не пустота.

## 3. Что удаляется из контрактов

### Серверные

Весь модуль Jitsi. После правки любой запрос к `/api/v1/meetings` отвечает
**404** — маршрут не смонтирован:

| Метод | Путь |
|---|---|
| `GET` | `/api/v1/meetings/` |
| `POST` | `/api/v1/meetings/` |
| `POST` | `/api/v1/meetings/{id}/end` |

Таблица `meetings` удаляется миграцией. Миграция обязана быть безопасна при
повторном применении: на этом проекте `create_all` отрабатывает раньше
`alembic upgrade`, поэтому `op.drop_table` защищается проверкой
`has_table("meetings")`.

### Клиентские

- Строка поиска в меню и сочетание `Ctrl+K`, которое её открывало.
- Ключи `search.placeholder`, `search.noResults`, `search.courses`,
  `search.lessons` — во всех шести локалях. Принцип V: мёртвый ключ удаляется,
  а не хранится «на всякий случай».
- Весь раздел `meet.*` — он обслуживал только Jitsi.
- Пункты меню «Онлайн-уроки» и «Записи» вместе с ключом `nav.recordings`.
  Раздел `recordings.*` **остаётся**: его строки нужны новому списку.
- Тип `Meeting` в `types/api.ts`.

### Чего в этом списке нет намеренно

- `lib/meetings.ts` и функция `buildJoinUrl` — их зовут журнал и расписание
  для ссылок на кабинеты и слоты. Имя обманывает, назначение другое.
- `rooms.meeting_url`, ссылка встречи у слота расписания, `EventType.meeting`.
- Эндпоинт `/courses/search/`: остаётся без потребителей после переноса
  поиска, но к меню отношения не имеет. Отдельная уборка, отмечено в спеке в
  разделе «Out of scope».
