# Contracts: Меню короче, настройки школы достижимы

**Feature**: `specs/033-menu-and-org-settings`
**Date**: 2026-08-20

Новых эндпоинтов задача не заводит. Здесь два раздела: что уже обещает сервер
и на что опирается интерфейс, и что интерфейс обещает пользователю сам.

---

## 1. Серверные контракты — существующие, не меняются

### `GET /api/v1/admin/organizations`

Кто: любая роль администратора. Суперадмин получает все организации, остальные
— только свою. Это уже так работает, и на этом держится FR-019: администратору
школы в списке просто нечего открыть, кроме себя.

Ответ — массив объектов:

```json
[
  {
    "id": "<uuid>",
    "name": "Пример школы",
    "slug": "primer-shkoly",
    "is_active": true,
    "settings": { "display_name": "Пример школы", "primary_color": "#22c55e" },
    "created_at": "2026-01-15 10:30:00+00:00"
  }
]
```

### `GET /api/v1/admin/organizations/{org_id}`

Кто: суперадмин — любую организацию; администратор школы — только свою.
Чужая организация отдаёт **404, а не 403** — так требует принцип I
конституции, и так сервер уже отвечает (`NotFoundError`).

Ответ — один объект той же формы.

### `PUT /api/v1/admin/organizations/{org_id}`

Кто: те же права, та же реакция на чужую организацию.

Тело — все поля необязательны:

| Поле | Тип | Примечание |
|---|---|---|
| `name` | `string \| null` | Название организации |
| `is_active` | `boolean \| null` | Применяется **только** для суперадмина; администратору школы поле молча игнорируется |
| `settings` | `object \| null` | Сливается с существующим блоком, не заменяет его |

Пример запроса, который шлёт экран настроек:

```json
{
  "name": "Пример школы",
  "settings": {
    "display_name": "Пример школы",
    "logo_url": "",
    "primary_color": "#22c55e",
    "secondary_color": "#3b82f6",
    "menu_visibility": { "crm": false }
  }
}
```

**Слияние, а не замена** — важная деталь: сервер делает
`current.update(data.settings)`. Клиент может слать только изменившиеся ключи,
и настройки, о которых экран не знает, не сотрутся.

### Что интерфейс НЕ делает

Не проверяет права сам. Клиентская проверка «показывать ли кнопку» — это
оформление, а не контроль; судит сервер. Экран, открытый по прямой ссылке на
чужую организацию, обязан честно показать «не найдено» из ответа сервера, а не
угадывать заранее.

## 2. Контракты интерфейса

### 2.1. Боковое меню

| Элемент | Обещание |
|---|---|
| Кнопка сворачивания | Видна на экранах от 768 px. Имеет доступное имя. Переключает `collapsed` в сторе |
| Рельс (свёрнутое меню) | Показывает логотип школы и её название. Пункты — иконки. У каждой иконки есть `aria-label` и подсказка по наведению и по фокусу |
| Заголовок категории | `<button>` с `aria-expanded` и `aria-controls`, указывающим на `id` её списка |
| Список категории | `<ul>` с тем самым `id`. Скрыт, когда категория свёрнута |
| Активный пункт | `aria-current="page"`. Виден даже внутри свёрнутой категории |
| Пустая категория | Не отрисовывается вовсе — ни заголовка, ни списка |

Клавиатура: порядок обхода совпадает с порядком на экране. Заголовок категории
получает фокус до своих пунктов. Пункты свёрнутой категории выпадают из обхода
вместе со списком.

Движение: переход 150–300 мс на `transform`/`opacity`. При
`prefers-reduced-motion: reduce` перехода нет.

### 2.2. Объединённая страница онлайн-уроков

Адрес: `/admin/meetings`. Вкладка — в параметре `?tab=`.

| Значение `tab` | Что показывает |
|---|---|
| отсутствует или неизвестное | Встречи — поведение по умолчанию |
| `meetings` | Встречи: текущие и прошедшие |
| `recordings` | Записи |

Неизвестное значение не роняет страницу и не даёт пустой экран — открывается
вкладка по умолчанию. Тот же приём уже применён на `/admin/journal`.

Действия, которые обязаны остаться (FR-013):

| Действие | Кто может |
|---|---|
| Создать встречу | преподаватель, администратор, суперадмин |
| Войти ведущим | автор встречи и все три роли выше |
| Завершить встречу | те же |
| Посмотреть запись | все, кто видит страницу; кнопка недоступна, пока `status ≠ ready` |
| Поделиться записью с группой | те же |
| Удалить запись | **только** администратор и суперадмин |

### 2.3. Редирект

`/admin/recordings` → `/admin/meetings?tab=recordings`, временный
(`permanent: false`), объявлен в `redirects()` файла `frontend/next.config.ts`.

Временный, а не постоянный: постоянный редирект браузер кэширует надолго, и
если адрес когда-нибудь вернётся, старые браузеры о нём не узнают. Две
существующие записи для снятого `/sat-practice` в том же блоке сделаны так же.

### 2.4. Экран настроек организации

Адрес: `/admin/organizations/{orgId}`.

| Состояние | Что видит пользователь |
|---|---|
| Загрузка | Индикатор ожидания |
| Успех | Форма с названием, логотипом, двумя цветами и переключателями видимости пунктов |
| Организация не найдена или чужая | Сообщение «не найдено» — одинаковое в обоих случаях, чтобы существование чужой школы не подтверждалось |
| Сохранено | Подтверждение; значения на форме совпадают с сохранёнными |

Форма — один компонент `org-settings-form.tsx` с обязательным пропом `orgId`.
Умолчания у `orgId` нет: именно молчаливое умолчание на `user.org_id` и делает
сегодняшний `/admin/settings` неспособным править чужую школу.

### 2.5. Фильтр курсов

Строка на `/admin/courses`. Сужает уже загруженный список по вхождению
подстроки в название, без учёта регистра. Пустая строка показывает всё. Когда
совпадений нет, на месте списка — сообщение, а не пустота.

## 3. Что удаляется из контрактов

- Строка поиска в меню и сочетание `Ctrl+K`, которое её открывало.
- Ключи перевода `search.placeholder`, `search.noResults`, `search.courses`,
  `search.lessons` — во всех шести локалях. Принцип V: мёртвый ключ удаляется,
  а не хранится «на всякий случай».
- Пункт меню «Записи» и ключ `nav.recordings`. Сам раздел `recordings.*`
  остаётся: его строки нужны объединённой странице.

Эндпоинт `/courses/search/` на сервере остаётся без потребителей. Не трогаем:
удаление эндпоинта — правка бэкенда, а фича фронтендовая. Отмечено в спеке, в
разделе «Out of scope».
