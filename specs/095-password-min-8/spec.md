# 095 — один минимум пароля: 8 символов

**Ветка**: `fix/password-min-8-095` · **Создано**: 2026-10-08

## Что не так

Минимальная длина пароля зависела от того, каким путём его задают:
- смена пароля в профиле требует 8 (`/auth/change-password`);
- регистрация и профиль на фронте пишут «не меньше 8»;
- сброс пароля по ссылке из письма принимал 6: и бэкенд
  (`/auth/reset-password`), и страница `/reset-password` с подсказкой
  `auth.phMin6`. Текст ошибки `auth.passwordTooShort` во всех шести языках тоже
  говорил «6».

Через сброс можно было поставить пароль, который смена пароля не приняла бы.

## Что меняется

- Правило одно: не меньше 8 символов, строгое из двух.
- `ResetPasswordRequest.new_password` получает `min_length=8` в схеме; ручная
  проверка `< 6` в обработчике удаляется. Короткий пароль отклоняется с 422 до
  того, как сервер смотрит на токен; токен остаётся неиспользованным.
- Страница `/reset-password` проверяет `< 8` и показывает `auth.phMin8`.
- Ключ `auth.phMin6` удаляется из всех шести локалей: других потребителей у него
  нет. `auth.passwordTooShort` во всех шести говорит «8».

Вне спеки: бэкенд регистрации длину пароля не проверяет вовсе, ограничение есть
только на фронте. Это отдельная правка.

## Проверка

- pytest на настоящем postgres: сброс с паролем из 7 символов по живому токену
  отклоняется, хеш пароля не меняется, токен не помечен использованным; тот же
  токен с паролем из 8 символов проходит (положительный контроль).
- vitest (`translations.test.ts` и остальные) и `tsc --noEmit` без ошибок.
