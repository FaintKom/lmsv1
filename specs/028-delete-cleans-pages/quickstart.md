# Quickstart: проверить, что удаление убирает за собой

## Что нужно

Postgres из `docker-compose.yml` (образ обязан быть `pgvector/pgvector:pg16`
— расширения `vector` в стоковом postgres нет, и без него метадата не
поднимется):

```bash
docker compose up -d db
```

## Красные тесты — до кода

Сначала прогнать новый файл против нынешнего поведения. Он обязан упасть:
сегодня удаление ссылку не убирает, и падение — доказательство, что тест
способен упасть (принцип II конституции).

```bash
cd backend && python -m pytest tests/test_exercise_delete_cleanup.py -v
```

Ожидание до реализации: падают проверки «блок исчез со страницы»,
«`sort_order` пересобран», «пустая страница осталась». Проходит только
отрицательная — «чужой урок не тронут», — и именно поэтому её одной было бы
недостаточно.

## Зелёные тесты — после кода

```bash
cd backend && python -m pytest tests/test_exercise_delete_cleanup.py -v
```

```bash
cd backend && python -m pytest -q
```

Второй прогон — весь бэкенд: уборка живёт в пути удаления, которым
пользуются и другие тесты.

## Проверка в браузере

1. Курс → урок → страница, на которой стоят текст, задание и ещё текст.
2. Открыть каталог заданий, удалить то самое задание.
3. Вернуться в редактор урока: на странице два текстовых блока подряд, без
   пустого места между ними.
4. Открыть урок глазами ученика (`/courses/<id>/lessons/<id>`): страница
   читается связно, кнопка Next на месте, номер страницы в адресе прежний.

Шаг 3 — тот, ради которого всё делается: сегодня там остаётся заглушка.

## Проверка в проде — один раз, на чистке

После выката: удалить 24 негодных задания и убедиться, что висящих ссылок
стало ноль (без правки их осталось бы 21). Запрос читает и ничего не пишет:

```sql
select count(*) from lessons l,
       jsonb_array_elements(l.content->'pages') p,
       jsonb_array_elements(p->'blocks') b
where b->>'type' = 'exercise'
  and not exists (select 1 from exercises e where e.id::text = b->>'exercise_id');
```

Ожидание: `0`.
