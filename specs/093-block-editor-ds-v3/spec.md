# 093 — блочный редактор на DS v3

**Ветка**: `fix/editor-ds-v3` · **Создано**: 2026-10-08

## Что не так

Методист пишет урок в блочном редакторе, а ученик читает его в
`.lms-lesson-content`. Это были два разных оформления:
- редактор жил на старой палитре: индиго `#6366f1` в ссылках, инлайн-коде,
  цитатах и фокусе, серые `#64748b`/`#94a3b8`, тёмно-фиолетовый фон кода;
- в callout перед текстом стояло эмодзи (ℹ️ ⚠️ ✅ ❌), а вид заметки держался на
  цветной полосе слева толщиной 4px;
- плейсхолдер пустого абзаца был `#94a3b8` на белом — ниже 4.5:1.

Оба файла были в EXEMPT дизайн-теста, поэтому проверка их не видела.

## Что меняется

- `editor-styles.css` переведён на токены DS v3 и совпадает с тем, что видит
  ученик: код на ink-900, инлайн-код на surface-2, ссылки и маркеры списков
  в `--color-primary-text`, цитата с нейтральной линией 2px, фокус в
  `--color-border-focus`. Тёмная тема работает через токены, без отдельных
  правил.
- Плейсхолдер — `--color-text-muted`.
- Callout: рамка 1px вместо полосы, нарисованная иконка (lucide: info,
  triangle-alert, circle-check, circle-x) вместо эмодзи, `role="note"`.
  Формат сохранения не меняется: урок хранится в JSON, атрибут `variant` тот же.
- Предупреждение стояло на постоянном светлом `bg-sun-50`; в тёмной теме на нём
  светлый текст не читался (найдено на стенде). Теперь `bg-warning-soft`,
  который меняется вместе с темой.
- Оба файла убраны из EXEMPT: дизайн-тест теперь их проверяет.

## Проверка

- `tsc --noEmit` без ошибок.
- `callout.test.ts`: для каждого варианта в HTML есть `<svg>` и
  `role="note"`, нет эмодзи и полосы; неизвестный вариант падает в info.
- Дизайн-тест зелёный без исключений для редактора, детектор impeccable по
  `components/editor` пуст.
