# Feature Specification: Language & Word-Game Authoring Tools

**Feature Branch**: `feat/language-tools`
**Created**: 2026-08-20
**Status**: Draft
**Input**: Этап 6 плана tasks/feedback-2026-08-19-authoring.md — замечания владельца 6, 7, 25, 26, 29, 30ч. Замечание 24ч (языки перевода вводятся текстом) уже выполнено — редактор перевода держит два свободных текстовых поля.

## User Scenarios & Testing

### User Story 1 — Crossword builds itself from the word list (P1, замечание 29)

Учитель вводит слова и определения. Кнопка «Собрать сетку» раскладывает слова с пересечениями сама; ручные Row/Col/направление и «Place on grid» уезжают в свёрнутый продвинутый режим для точечной правки. Определение на слово уже есть — остаётся.

**Why this priority**: сейчас составить кроссворд руками — самая дорогая операция каталога: подбор координат на глаз, конфликты, «Place on grid» по слову.

**Acceptance**:
1. **Given** 6 слов с определениями, **When** учитель жмёт «Собрать сетку», **Then** все 6 слов лежат в сетке без конфликтов букв, хотя бы часть — с пересечениями, превью показывает результат.
2. **Given** слово, которое ни с чем не пересекается, **When** сборка, **Then** оно размещено отдельно (без пересечений — допустимо), а не потеряно.
3. **Given** собранную сетку, **When** учитель открывает продвинутый режим и двигает слово, **Then** ручная правка работает как раньше.
4. **Given** слова, которые не влезают в размер сетки, **Then** внятное сообщение — какие слова не поместились; сетка не портится.

### User Story 2 — Word search seen before it is assigned (P1, замечание 30ч)

Редактор word search показывает сгенерированную сетку. Кнопка «Перегенерировать» даёт новый вариант; выбранная раскладка сохраняется с упражнением, и ученик получает ровно её (сейчас плеер генерирует случайную сетку на каждое открытие — учитель в принципе не видел того, что видит ученик).

**Acceptance**:
1. **Given** список слов, **When** редактор открыт, **Then** видна сетка со спрятанными словами; **When** «Перегенерировать», **Then** раскладка другая.
2. **Given** сохранённое упражнение, **When** ученик открывает его дважды, **Then** сетка оба раза одна и та же и совпадает с той, что видел учитель.
3. **Given** старое упражнение без сохранённой раскладки, **Then** оно работает как раньше (сетка от слов, стабильная в рамках попытки).

### User Story 3 — Sentence builder from pasted text (P2, замечание 25)

Учитель вставляет предложение целиком — оно само разбивается на слова в правильном порядке. Ученик получает слова перемешанными.

**Acceptance**:
1. **Given** пустой редактор, **When** учитель вставляет «Der Hund läuft im Park» в поле «вставить предложение», **Then** появляются 5 слов в правильном порядке, доступные для правки поштучно.
2. **Given** сохранённое упражнение, **When** ученик открывает его, **Then** слова показаны в порядке, отличном от правильного (кроме вырожденных случаев из 1–2 слов).

### User Story 4 — The dialogue editor says which answer is right (P2, замечание 26)

В точке выбора рядом с каждым вариантом стоит немаркированный кружок-радио — «странное поле». Выбор правильного ответа получает подпись/оформление, из которого ясно: этим отмечают правильную реплику.

**Acceptance**:
1. **Given** точка выбора с 3 вариантами, **Then** у элемента выбора правильного ответа есть текстовая подпись (колонка «правильный» или подписанные контролы), и отмеченный вариант визуально отличим.

### User Story 5 — Test cases arrive as a file (P2, замечание 6)

Учитель загружает CSV с тест-кейсами code challenge (колонки: input, expected_output, is_hidden) вместо набивания по одному. Рядом — скачиваемый файл-эталон формата. Текст задания уже есть (поле Instructions) — спека фиксирует, что он доходит до ученика в плеере.

**Acceptance**:
1. **Given** CSV из 10 строк по эталону, **When** загрузка, **Then** 10 тест-кейсов создаются и видны в списке; количество подтверждается.
2. **Given** битый CSV (нет колонки expected_output), **Then** понятная ошибка со ссылкой на эталон; ничего не импортируется наполовину.
3. **Given** кнопка «Скачать шаблон», **Then** скачивается CSV с шапкой и парой строк-примеров.
4. **Given** упражнение с заполненным Instructions, **When** ученик открывает code challenge, **Then** текст задания виден.

### User Story 6 — Fill blanks hint sits under the input (P3, замечание 7)

Подсказка о пропусках показывается под полем ввода/зоной ответа, а не в отдалении. Поле правильных ответов на каждый пропуск и маркеры __ уже есть в редакторе — констатация, не работа.

**Acceptance**:
1. **Given** упражнение fill blanks в плеере, **Then** подсказка про заполнение расположена непосредственно под зоной ответа.

### Edge Cases

- Кроссворд: одно слово; слова с общей буквой в несовместимых позициях; кириллица.
- Word search: слово длиннее сетки — сообщение, не бесконечный цикл; старые сабмишены не ломаются.
- Sentence builder: двойные пробелы, знаки препинания при вставке — прилипают к словам, не становятся отдельными фишками.
- CSV: кавычки и запятые внутри input; CRLF/LF; BOM; пустые строки.

## Requirements

### Functional Requirements

- **FR-001**: Редактор кроссворда собирает раскладку из списка слов одним действием; конфликтов букв в результате нет.
- **FR-002**: Ручное позиционирование слова остаётся доступным, но не является основным режимом.
- **FR-003**: Слова, не поместившиеся в сетку, названы поимённо; частичная раскладка валидна.
- **FR-004**: Редактор word search показывает точную сетку ученика и умеет перегенерацию; выбранная раскладка воспроизводима после сохранения.
- **FR-005**: Существующие word search без сохранённой раскладки продолжают работать.
- **FR-006**: Sentence builder принимает вставленный текст и разбивает его на слова в правильном порядке; ученик видит слова перемешанными.
- **FR-007**: Отметка правильного ответа в редакторе диалога подписана и визуально однозначна.
- **FR-008**: Тест-кейсы code challenge импортируются из CSV (input, expected_output, is_hidden); формат описан скачиваемым эталоном; ошибки формата не приводят к частичному импорту.
- **FR-009**: Текст задания code challenge (Instructions) виден ученику в плеере.
- **FR-010**: Подсказка fill blanks в плеере стоит под зоной ответа.
- **FR-011**: Скрытые тест-кейсы (is_hidden) не доходят до ученика ни в каком виде — импорт не ослабляет действующее правило.

### Key Entities

- **Crossword layout**: слова + позиции/направления, производные от списка слов; хранится в конфиге упражнения.
- **Word search layout**: детерминированная раскладка (сетка или зерно генерации) в конфиге.
- **Test case**: input, expected_output, is_hidden — уже существующая сущность; CSV лишь способ ввода.

## Success Criteria

- **SC-001**: Кроссворд из 8 слов собирается за меньше чем минуту работы учителя (сейчас — минуты ручного подбора координат на слово).
- **SC-002**: Учитель word search видит до сохранения ровно ту сетку, что увидит ученик; два открытия у ученика дают одну сетку.
- **SC-003**: 10 тест-кейсов попадают в упражнение одной загрузкой файла.
- **SC-004**: Предложение из 8 слов превращается в упражнение sentence builder одной вставкой.
- **SC-005**: Ни один ответ/скрытый кейс не доступен ученику до сдачи (правило Integrity сохранено).

## Assumptions

- «Файл-эталон оформления» из замечания 6 = скачиваемый шаблон CSV с примерами строк.
- Замечание 24ч выполнено ранее (языки — свободный текст в редакторе перевода) — работы нет.
- В fill blanks поле ответов и маркеры __ уже есть — работа только над положением подсказки в плеере.
- Автогенератор кроссворда — эвристика (жадное перекрещивание), не оптимальный солвер: полнота раскладки не гарантируется, негарантированные слова честно перечисляются.
