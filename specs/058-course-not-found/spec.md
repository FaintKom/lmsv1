# Чужой курс по прямой ссылке даёт пустой экран

**Дата**: 2026-08-23 · **Ветка**: `fix/walkthrough-course-not-found` · **Статус**: разобрано

## Что происходит

Ручной прогон 2026-08-23 (Н-15 в `tasks/walkthrough-2026-08-23-full-path.md`)
проверял изоляцию школ: ученик новой школы открыл ссылку на курс чужой.

Сервер ответил правильно — 404, чужого курса ученик не увидел. А экран остался
пустым: ни заголовка, ни объяснения, ни выхода. Изоляция сработала, интерфейс
об этом не сказал.

Тот же экран получает всякий, кто пришёл по устаревшей ссылке или ошибся в
адресе, — а это случается чаще, чем попытка заглянуть в соседнюю школу.

## Причина

```tsx
apiClient.get(`/courses/${params.courseId}`)
  .then(({ data }) => setCourse(data))
  .catch(() => {})                       // <- ошибку проглотили
  .finally(() => setLoading(false));

if (loading || !course) return <Skeleton />;
```

`loading` снимается, `course` остаётся `null` — и условие держит страницу в
скелете навсегда. Отказ и загрузка выглядят одинаково, потому что состояние
«не нашлось» в компоненте не заведено.

## Решение

Отдельное состояние `missing` и отдельный экран: «Course not found» и ссылка
обратно в каталог. Ключи `admin.courseEdit.notFound` и `nav.courses` уже есть
во всех шести локалях — новых слов не понадобилось.

Сообщение намеренно одно на оба случая: курса нет и курс чужой. Разные ответы
рассказали бы постороннему, какие курсы существуют, — 404 на чужое здесь
осознанный выбор бэкенда, и экран его не выдаёт.

## Проверка

Ручная, после деплоя: открыть `/courses/<чужой-id>` учеником другой школы и
увидеть сообщение со ссылкой в каталог вместо бесконечного скелета.

Автотеста нет: проверять нечего, кроме отрисовки ветки на пойманной ошибке —
тест повторил бы саму правку, а не защищал поведение.
