# Interface Contracts: Menu visibility controls

**Date**: 2026-08-22 · **Spec**: [spec.md](../spec.md)

Что эта работа обещает наружу. Всё, чего здесь нет, менять нельзя.

---

## 1. Список скрываемых пунктов

Один упорядоченный список, состав — в [data-model.md](../data-model.md).

**Обещает:**

- он **единственное** место, где перечислено, что школа вправе скрыть;
- порядок объявления устойчив: форма показывает пункты в нём, и перестановка
  меняет то, что видит администратор;
- `labelKey` указывает на строку меню. Собственных строк у формы нет.

**Не содержит** пунктов без ключа видимости. Попадание туда `waitlist`,
`organizations` или `integrations` — ошибка: у них нечего выключать.

---

## 2. `buildNavTree` — та же карта для всех ролей

Функция уже существует. Меняется охват, не сигнатура.

| Роль | сегодня | после |
|---|---|---|
| администратор, учитель | карта спрашивается | без изменений |
| ученик | **не спрашивается** | спрашивается |
| родитель | **не спрашивается** | спрашивается |

**Обещает:**

- выключенный ключ убирает пункт у каждого, кто его видел (FR-015);
- пункт без ключа не трогается ничем;
- права не меняются: адрес страницы остаётся достижим тому, кому был разрешён
  (FR-013);
- школа, ничего не выключавшая, видит прежнее меню во всех ролях.

---

## 3. Две проверки, ловящие следующее расхождение

Не тест конкретных пунктов, а обещание, что список и дерево не разойдутся.
Разрыв уже возникал дважды и месяцами не был виден.

**А. Каждый ключ что-то выключает.** Для каждого ключа: дерево со всеми
включёнными, затем выключить только этот — исчезает ровно один пункт.

Падает, когда ключ есть в списке, а дерево его не спрашивает.

**Б. Дерево не спрашивает ничего сверх списка.** Выключить все ключи списка;
остаться должны ровно пункты без ключа — сводка, лист ожидания, организации,
интеграции.

Падает, когда пункту дали ключ, но забыли внести в список: он останется на
экране и не совпадёт с этим перечнем. **Сегодня падает на шести лишних.**

Обе выполняются для каждой роли, у которой есть своё меню.

---

## 4. `<MenuVisibilitySection />`

**Вход:** карта видимости и обработчик изменения. Больше ничего.

**Обещает:**

- переключатель для каждой записи списка, в порядке списка;
- группировку по категориям меню, с их заголовками и в их порядке;
- пометку «только администратор» там, где `adminOnly`;
- подпись, дословно совпадающую с подписью пункта в меню;
- предупреждение под выключенной «Поддержкой» — и ничего, пока она включена;
- предупреждение **не** блокирует сохранение.

**Не имеет доступа** к организации, к сети и к сохранению. Если ей однажды
понадобится `orgId` — граница проведена неверно, как это уже решено для превью
бренда в `specs/037`.

---

## 5. Что сохраняет форма

**Обещает:**

- карта содержит ровно ключи списка;
- значение каждого ключа — то, что администратор видел на экране, включая
  загруженные и не тронутые им;
- сохранение без единого изменения оставляет карту прежней;
- ключи, которых нет в списке, в сохранённую карту не попадают — так из настроек
  ушёл `meetings` (`specs/039`).

**Прямое следствие, которое легко нарушить:** карта не собирается «все включены,
кроме отмеченных». Она собирается из загруженных значений.

---

## 6. Строки перевода

- Подписи пунктов берутся из `nav.*`.
- Десять ключей `admin.settings.menu*` удаляются из шести локалей. Проверено:
  вне формы их не читает никто.
- Предупреждение о поддержке — один новый ключ в шести локалях.
