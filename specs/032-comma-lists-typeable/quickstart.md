# Quickstart — как убедиться, что правка работает

## Красный прогон до правки

Тест обязан упасть на сегодняшнем коде — иначе он ничего не проверяет
(принцип II конституции).

```bash
cd frontend && npx vitest run src/components/exercises/comma-list-input.test.tsx
```

Ожидаемое падение: поле показывает `xy`, ожидалось `x, y`.
Строку падения приложить к PR.

## Зелёный прогон и шлюзы

```bash
cd frontend && npx vitest run
```

```bash
cd frontend && npx tsc --noEmit
```

Парность локалей проверяет `translations.test.ts` внутри общего прогона —
ключ, забытый в одной локали, роняет его. Ключ, забытый во **всех шести**,
проходит молча: тест сверяет локали между собой, а не со словарём. Поэтому
подсказки надо посмотреть глазами в браузере, а не только в тестах.

## Браузер, стенд QA

```bash
docker compose -f docker-compose.qa.yml up -d --wait
```

Второму чату — свой `.env.qa.local` и `--env-file` в каждой команде.

Пройти четыре места, в каждом набрать список **с клавиатуры**, не вставкой:

| Где | Что набрать | Что должно получиться |
|---|---|---|
| Система уравнений → переменные | `x, y` | в поле `x, y`; строка ключа показывает решение, а не отказ сервера |
| Короткий ответ → ещё принимаются | `paris, Paris` | оба варианта сохранились |
| Загрузка файла в карточке задания | `.pdf, .png` | два расширения |
| Загрузка файла в блоке урока | `.pdf, .png` | два расширения |

Отдельно — то, чего тесты в jsdom не проверяют:

- поставить курсор в середину заполненного поля, дописать символ; курсор
  остаётся на месте, текст не переставляется;
- открыть другое задание того же типа — поле показывает его список,
  а не прежний.

## В проде после выката

На задании «New System of Equations»: набрать `x, y` с клавиатуры и
убедиться, что строка ключа показывает решение. До правки она говорила
«These are not linear equations in the variables above — the server will
refuse the submission».

Сохранять правку в чужом задании не нужно — достаточно того, что показывает
форма.
