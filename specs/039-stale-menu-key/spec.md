# Feature Specification: A menu key for a feature that no longer exists

**Feature Branch**: `fix/stale-menu-key`

**Created**: 2026-08-22

**Status**: Draft

**Input**: Владелец: «убери meetings из карты видимости».

## Контекст

Каждая школа хранит карту видимости пунктов меню в `organizations.settings`
под ключом `menu_visibility`. В проде у обеих школ с настройками там лежит
`"meetings": true` — пункт, удалённый вместе с модулем Jitsi в
`specs/033-menu-and-org-settings`.

Вреда нет: меню читает карту по ключам существующих пунктов, лишний
игнорируется. Но это ложь в данных. Тот, кто откроет настройки школы, чтобы
понять, что она скрывает, прочтёт про пункт, которого нет.

Форма настроек этот ключ **не пишет** — она собирает карту заново из своего
списка. Значит при следующем сохранении настроек он исчезнет сам. Но ни одна
школа с тех пор настройки не сохраняла, и полагаться на то, что когда-нибудь
сохранит, — не решение.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - В настройках школы нет пунктов, которых нет в продукте (Priority: P1)

Человек читает настройки школы — через интерфейс, через API или прямо в базе —
и видит только те пункты меню, которые в продукте существуют.

**Why this priority**: единственная причина этой работы. Данные, описывающие
несуществующее, однажды кого-нибудь заведут не туда.

**Independent Test**: прочитать `menu_visibility` у школы, которая до правки
содержала `meetings`, и убедиться, что ключа больше нет, а остальные на месте.

**Acceptance Scenarios**:

1. **Given** школа хранит `menu_visibility` с ключом `meetings`, **When**
   применена миграция, **Then** ключа `meetings` в карте нет.
2. **Given** та же школа, **When** применена миграция, **Then** все остальные
   ключи и их значения не изменились.
3. **Given** школа без `menu_visibility` или без настроек вовсе, **When**
   применена миграция, **Then** её настройки не изменились и ошибки не было.
4. **Given** миграция уже применялась, **When** она применяется снова, **Then**
   ничего не меняется и ошибки нет.

### Edge Cases

- `settings` пуст или отсутствует — миграция его не трогает.
- `menu_visibility` есть, но `meetings` в нём нет — школа не затрагивается.
- `menu_visibility` не словарь (испорченная запись) — миграция её не трогает,
  а не падает на всей базе.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Ключ `meetings` MUST быть удалён из `menu_visibility` у всех школ.
- **FR-002**: Остальные ключи карты MUST остаться нетронутыми, вместе со
  значениями.
- **FR-003**: Школы без этого ключа MUST остаться нетронутыми.
- **FR-004**: Повторное применение MUST быть безопасным.
- **FR-005**: Откат MUST NOT возвращать ключ: он описывает удалённую фичу, и
  вернуть его — значит вернуть ту же ложь.

### Key Entities

- **Карта видимости меню**: словарь в `organizations.settings.menu_visibility`,
  ключи — идентификаторы пунктов меню, значения — булевы. Законный набор ключей
  задан списком в форме настроек школы.

## Success Criteria *(mandatory)*

- **SC-001**: Ни у одной школы в проде нет ключа `meetings` в карте видимости.
- **SC-002**: Ни одна школа не потеряла и не изменила ни одной другой настройки.
- **SC-003**: Ни один пункт меню не изменил видимости для кого бы то ни было.

## Assumptions

- Схема не меняется: `settings` — колонка `JSONB`, правится только её
  содержимое.
- Правка данных в проде идёт миграцией через GitHub, а не руками по SSH.
- Форма настроек уже пишет актуальный список ключей (`live` вместо `meetings`),
  проверено по коду; поэтому ключ не вернётся после первого же сохранения.

## Out of scope

Форма настроек даёт переключить **десять** пунктов, а меню умеет скрывать
**тринадцать**: `crm`, `journal` и `support` читаются кодом меню, но контролов
для них в форме нет. Это отдельный разрыв, крупнее этого, и он требует своей
спеки — здесь только удаление мёртвого ключа.
