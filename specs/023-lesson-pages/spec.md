# Feature Specification: Lesson Pages

**Feature Branch**: `feat/lesson-pages`
**Created**: 2026-08-20
**Status**: Draft
**Input**: Обратная связь владельца 2026-08-20: «есть модуль, внутри него уроки. в уроке должны быть блоки, внутри которых либо текст, видео, либо презентация, либо Html либо задания. блок не привязан к какому-то типу, это как просто страница, на которую добавляется контент. в одном блоке может быть текст и несколько заданий… один блок — это одна страница, которую может скролить ученик, пока не нажмет next». Плюс: «сейчас невозможно добавить блок в урок… открывается все в одной лентой».

## Терминология

Слово «блок» у владельца означает **страницу** — группирующий контейнер.
Внутри страницы лежат **элементы**: текст, видео, презентация, HTML,
задание, assignment. Ниже «страница» = блок владельца, «элемент» = кусок
контента внутри неё. Один урок = упорядоченный список страниц.

## Диагноз текущего состояния (почему «невозможно добавить»)

1. Кнопка «add block» в редакторе урока прозрачна (`opacity-0`) и
   проявляется только при наведении на пустую полосу между блоками —
   владелец её не нашёл. Добавление обязано быть постоянно видимым.
2. Урок отдаётся ученику одной сплошной лентой (у QA Lesson — 231
   элемент подряд); группировки и «Next» внутри урока нет.

## User Scenarios & Testing

### User Story 1 — Постоянно видимое добавление (P1)

Учитель открывает урок и сразу видит, куда нажать: в конце каждой
страницы — постоянная кнопка «Добавить контент» (текст / видео /
презентация / HTML / задание / assignment), под последней страницей —
постоянная кнопка «Добавить страницу». Hover-зоны между элементами
остаются как быстрый путь, но не единственный.

**Acceptance**:
1. **Given** урок без контента, **When** редактор открыт, **Then** без
   единого наведения мыши видны «Добавить контент» и «Добавить
   страницу».
2. **Given** страница с текстом, **When** учитель жмёт «Добавить
   контент» → «Задание» → тип, **Then** задание появляется в конце этой
   страницы; автосейв как раньше.

### User Story 2 — Страницы в редакторе (P1)

Контент урока сгруппирован в страницы: каждая страница — визуально
очерченная секция с номером/заголовком, своими элементами и своим
«Добавить контент». Страницы можно переставлять и удалять (удаление
страницы с контентом — с подтверждением). Элементы перетаскиваются в
пределах страницы.

**Acceptance**:
1. **Given** урок из 2 страниц, **Then** редактор показывает две
   очерченные секции; у каждой свой набор элементов.
2. **When** учитель двигает страницу 2 выше страницы 1, **Then** порядок
   меняется и сохраняется.
3. **Given** страница с текстом и двумя заданиями, **Then** все три
   элемента лежат внутри одной секции — смешение типов на странице
   работает.

### User Story 3 — Ученик листает страницы (P1)

Ученик открывает урок и видит ТОЛЬКО первую страницу: скроллит её до
конца, внизу — кнопка «Next» и прогресс «страница X из Y». Next ведёт на
следующую страницу (скролл вверх). На последней странице — прежний
переход к следующему уроку.

**Acceptance**:
1. **Given** урок из 3 страниц, **When** ученик открывает его, **Then**
   видна страница 1 и «1 / 3»; элементы страниц 2–3 не отрисованы.
2. **When** ученик жмёт Next, **Then** страница 2, «2 / 3», проскроллено
   к началу.
3. **Given** последняя страница, **Then** вместо внутристраничного Next —
   существующий переход «следующий урок».
4. **Given** перезагрузка на странице 2, **Then** ученик возвращается на
   страницу 2 (позиция в адресе).

### User Story 4 — Старые уроки живут без миграции (P1)

Урок, сохранённый до этой фичи (плоский список блоков или одиночный
текст), открывается как ОДНА страница со всем контентом — ровно то, что
ученик видел вчера. Редактор показывает его одной страницей; первое
сохранение переводит формат на страницы.

**Acceptance**:
1. **Given** урок этапа 2 (плоские блоки), **When** ученик открывает
   его, **Then** контент идентичен прежнему — одна лента, прежний Next
   на следующий урок.
2. **Given** тот же урок в редакторе, **Then** он показан одной
   страницей; «Добавить страницу» позволяет начать группировку.

### User Story 5 — Презентация как элемент (P2)

Новый тип элемента «Презентация»: учитель вставляет embed-ссылку
(опубликованные Google Slides, PDF по URL) — ученик видит её во
встроенной рамке на странице.

**Acceptance**:
1. **Given** элемент «Презентация» со ссылкой на опубликованные Google
   Slides, **Then** ученик видит слайды во встроенной рамке.
2. **Given** пустая/невалидная ссылка, **Then** учитель видит подсказку
   о формате, ученик — аккуратную заглушку, не сломанную рамку.

### Edge Cases

- Урок из 231 элемента (QA Lesson): открывается одной страницей,
  редактор не виснет; страницы позволяют потом разрезать.
- Страница без элементов: показывается пустой (честно), а редактор
  подсказывает её заполнить или удалить.
- Deep-link на страницу больше Y — показывается последняя.
- Ответы/прогресс заданий при листании: уход со страницы не теряет
  начатых заданий текущей сессии (поведение как при скролле).

## Requirements

### Functional Requirements

- **FR-001**: Добавление контента и страниц доступно постоянно видимыми
  органами управления, без наведения мыши.
- **FR-002**: Урок хранит упорядоченные страницы; каждая страница —
  упорядоченные элементы разных типов (текст, видео, презентация, HTML,
  задание, assignment) вперемешку.
- **FR-003**: Ученик видит одну страницу за раз, прогресс «X из Y»,
  Next; последняя страница ведёт к следующему уроку как раньше.
- **FR-004**: Позиция ученика в уроке восстанавливается по адресу
  страницы.
- **FR-005**: Уроки прежних форматов читаются как одна страница без
  миграции данных; их ученический вид не меняется, пока учитель не
  начал группировать.
- **FR-006**: Перестановка страниц и элементов внутри страницы;
  удаление страницы с подтверждением, если она не пуста.
- **FR-007**: Элемент «Презентация» принимает embed-ссылку и
  показывается ученику во встроенной рамке; невалидная ссылка не ломает
  страницу.
- **FR-008**: Ничего из механики ответов не меняется: задания на
  страницах проверяются как прежде, ответы не утекают (Integrity B).

### Key Entities

- **Page**: id, необязательный заголовок, упорядоченный список элементов.
- **Element**: существующие типы блоков этапа 2 (text, html, video,
  exercise, assignment) + новый presentation (embed URL).
- **Lesson content**: упорядоченный список страниц; прежние форматы
  интерпретируются как одна страница.

## Success Criteria

- **SC-001**: Учитель, впервые открывший редактор, добавляет страницу и
  задание без подсказок — органы управления видимы сразу (0 наведений
  мыши для обнаружения).
- **SC-002**: Ученик в уроке из 3 страниц проходит их по Next с
  прогресс-индикатором; на странице отрисованы только её элементы.
- **SC-003**: Ни один существующий урок не требует ручной правки после
  релиза; вид старых уроков для ученика не изменился.
- **SC-004**: Страница со смешанным контентом (текст + видео + 2
  задания) собирается в редакторе и проходится учеником целиком.

## Assumptions

- «Презентация» = embed-ссылка (Google Slides «publish to web», PDF по
  URL). Загрузка файлов презентаций — вне скоупа этой фичи.
- Прогресс «страница X из Y» не персистится в БД — позиция живёт в
  адресе; завершённость урока считается как раньше.
- Названия страниц опциональны; по умолчанию «Страница N».
