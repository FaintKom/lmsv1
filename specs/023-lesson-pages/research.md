# Research: Lesson Pages

- **Почему «невозможно добавить блок»**: AddZone в редакторе урока
  (admin/lessons/[lessonId]/edit/page.tsx:521–528) рисует кнопку с
  `opacity-0`, видимую только при hover на 6px-полосу. Найдено
  воспроизведением в браузере: 232 кнопки «add block» на странице, все
  невидимы без наведения.
- **Ученик получает ленту**: student page:542 рендерит все
  `content.blocks` при `version === 2`; Next существует только между
  уроками (nextLesson).
- **`normalize_lesson_content` безопасен для v3** (courses/service.py:31):
  проверка строго `== 2`; для v3 body/url отсутствуют → blocks пусты →
  content возвращается нетронутым. Бэкенд-формат менять не надо.
- **Тьютор сломается на v3** (tutor/router.py:95): `version != 2 →
  return ""` — урок в страницах потеряет текст для ask-виджета.
  Единственная обязательная бэкенд-правка: flatten pages в
  `_lesson_text`. RED-first.
- **Блоки уже несут `page: number`** — и в типе (types/api.ts:41), и в
  нормализаторе (courses/service.py:45, всегда 1). Соблазн сгруппировать
  по этому полю велик: ни нового формата, ни правки тьютора. Отвергнуто
  из-за авторского потока: страница, существующая только как номер на
  блоках, не может быть пустой, а владелец добавляет страницу и лишь
  потом её наполняет. Контейнер даёт пустую страницу бесплатно, плюс
  место под заголовок и перестановку страниц без переписывания номера у
  каждого блока.
  - Цена решения — ровно одна: `_lesson_text` тьютора учится обходить
    pages. Других читателей `content.blocks` нет (проверено грепом по
    backend/app).
- **Deep-link**: `?page=N` через useSearchParams — уже используется в
  редакторе (courseId/moduleId), паттерн знаком.
- **Presentation**: iframe c `sandbox` и http(s)-валидацией; Google
  Slides «publish to web» и PDF-URL работают в iframe. Отдельного
  бэкенд-хранения нет — url лежит в блоке.
- **v2-урок при первом сохранении** переводится в v3 (одна страница со
  всеми блоками) — обратный путь не нужен, extractPages читает оба.
